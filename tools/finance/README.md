# MARCOSA — модель чувствительности в месяц

Запуск из корня репозитория: `node tools/finance/run.mjs > /tmp/marcosa-scenarios.json`. Выход содержит девять комбинаций 10 тысяч, 100 тысяч и 1 миллион MAU и три набора допущений. Все суммы — условные рубли за месяц, а не реальные данные или рыночные оценки. Значения можно заменить через JSON-файл: `node tools/finance/run.mjs assumptions.json`. В файле используются разделы `all`, `pessimistic`, `base`, `optimistic`; значения раздела сценария имеют приоритет. Полные входы включены в каждый результат.

`ads = MAU × показы на пользователя × fill × eCPM / 1000`. Выручка подписок платформы = количество платящих × цена с корректировкой возвратов. Комиссия = успешный объём сделок × ставка. Contribution margin = сумма выручки минус указанные переменные расходы. Налоги — отдельный условный процент от положительной операционной прибыли, по умолчанию 0, так как юрисдикция не установлена. НДС, стоимость привлечения, фиксированные расходы и права на музыку/видео нужно отдельно проверять по рынку. Затраты разработки, маркетинга и операций указаны гипотезой и по умолчанию одинаковы при всех масштабах. Меняйте их в файле допущений в зависимости от стадии.

Модель перечисляет CDN, хранение, транскодирование, базы, push, модерацию, поддержку, платёжные комиссии и выплаты авторам с рекламы. Она предполагает, что MARCOSA оплачивает процессинг на полном объёме транзакций до возвратов. Оплата авторам по продажам уже исключена из комиссионной выручки. `boostSpend × boostMargin` отражает остаток выручки продвижения после подразумеваемого стороннего инвентаря, поэтому повторно добавлять его стоимость в расходы нельзя. Плата за брендовые сделки, Pro, SMB и продвижение по умолчанию равна нулю: данных для оценки нет. Модель не учитывает влияние продаж на рекламный инвентарь и удержание.

Для анализа чувствительности меняйте по отдельности `ecpm`, `fill`, `creatorBuyerRate`, `cdnPerMau`, `paymentRate` и фиксированные затраты. Для прибыльности сравнивайте операционную прибыль после настройки фиксированных затрат с contribution margin; отрицательный contribution margin на пользователя нельзя исправить ростом одной аудитории при прочих равных. Это учебная финансовая модель без подключения платежей и без утверждений о состоявшейся рекламе.

Проверка: `node --test tools/finance/model.test.mjs`.
