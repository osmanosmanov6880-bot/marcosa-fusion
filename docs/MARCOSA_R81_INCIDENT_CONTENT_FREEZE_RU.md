# MARCOSA R81 — аварийная заморозка изменений контента

**Сфера:** локальная Node.js 22 / SQLite лаборатория. НЕ облачный control plane, НЕ переключатель CDN, НЕ production readiness.

## Один большой операторский сценарий

При атаке, злоупотреблении, расхождении данных или расследовании инцидента оператор может остановить новые публикации и изменения контента без очистки базы:

```bash
MARCOSA_FREEZE_CONTENT=1 node server-lab/server.mjs
```

Сначала оператор останавливает предыдущий экземпляр. Это параметр **запуска процесса**: никакого сетевого выключателя, который можно случайно вызвать пользовательским запросом, здесь нет. Значения только `0` и `1`. Всё остальное отвергается до открытия HTTP-порта.

Когда режим включён, запрещены `POST/PATCH/DELETE` действия с контентом: создание аккаунтов, Worlds, публикаций и комментариев, загрузка/замена PNG, изменение подписок, заявки рекламодателей, одобрения новой обложки и другие небезопасные изменения. Ответ HTTP 503 с `Retry-After: 60`, `Cache-Control: no-store` и `X-Marcosa-Content-Freeze: active`. Сервер одинаково блокирует JSON и отдельный бинарный PNG upload path **до чтения тела**. Подмена Origin по-прежнему отвергается кодом 403.

Сохраняются безопасные **точно перечисленные** действия:

- Вход и выход из аккаунта по настоящему паролю/сессии, запрет анонимного обхода
- Смена пароля и отзыв других сессий с проверкой старого пароля
- Отзыв согласия на локальные наблюдения дней входа с удалением истории
- Экспорт своих данных (`GET`), удаление аккаунта по паролю и подтверждению
- Жалобы на опубликованный пост, комментарий или PNG и независимое скрытие поста/комментария либо решение по уже созданной жалобе на PNG

Смысл: предотвращать появление **нового контента**, не лишая пользователей права защитить себя, пожаловаться, выйти или удалить аккаунт. Вход во время инцидента по-прежнему создаёт новую сессию, а добровольно разрешённое измерение входов продолжает учитывать события. Следовательно, `contentWritesDisabled` означает именно остановку **контентных** изменений, а не физически неизменяемую БД.

Для одновременной остановки выдачи **публичных PNG** включить оба независимых флага R79/R81:

```bash
MARCOSA_DISABLE_PUBLIC_MEDIA=1 MARCOSA_FREEZE_CONTENT=1 node server-lab/server.mjs
```

Остаются приватные авторизованные предпросмотры, личный экспорт и кнопки безопасности. Сервис не удаляет материалы, жалобы и доказательства владельца в процессе freeze.

## Восстановление

Только после локальной независимой проверки инцидента, сохранения изолированного snapshot и решения ответственного оператора остановить процесс и запустить с `MARCOSA_FREEZE_CONTENT=0`. Отдельно проверить целостность SQLite, FK и существующие права пользователей; не включать публичные изображения без проверки прав на текущую PNG-версию.

## Реальная тестовая приёмка

`node --test server-lab/test/r81.content_freeze.test.mjs` создаёт три настоящих аккаунта и SQLite на диске. Проверяет: две опубликованные записи, перезапуск в двойном аварийном режиме, неизменность содержания при блокировке создания/редактирования/удаления, отдельный бинарный PNG path, заголовки 503, Origin 403, действующий экспорт, сохранность личных данных, отзыв consent, жалобу и независимое скрытие, удаление другого аккаунта по паролю, запрет stale-сессии и нормальную публикацию после повторного запуска. Отдельно — неправильный env и неверный тип параметра.

**Ограничение:** в production понадобятся согласованная межрегиональная остановка writes во всех worker-процессах, CDN и очередях, краткоживущие токены, контроль аудитора, аварийные разрешения и независимая проверка восстановления. Этот локальный флаг сам по себе не закрывает ни Supabase, ни правовую приёмку, ни Issue #55.
