# MARCOSA R82 — реальный пользовательский сигнал об инциденте

**Продукт:** локальная социальная платформа Node.js 22 / SQLite с RU/EN beta. Не публичный сайт и не Supabase production.

## Реализовано

Серверные аварийные режимы R79 (`MARCOSA_DISABLE_PUBLIC_MEDIA=1`) и R81
(`MARCOSA_FREEZE_CONTENT=1`) теперь видимы в интерфейсе без доверия к
локальным настройкам браузера. Сайт вызывает настоящий `GET /api/health`
и выбирает одно из четырёх состояний:

1. **healthy:** баннер скрыт, без декоративного предупреждения;
2. **content:** публикации и изменение контента приостановлены; экспорт,
   жалобы, безопасность аккаунта и удаление доступны;
3. **media:** публичные PNG скрыты; приватный предпросмотр остаётся
   доступен только авторизованному владельцу;
4. **both:** показано отдельное сообщение о двух одновременно работающих
   механизмах защиты.

Три сообщения переведены вручную на русский и английский (`incident.content`,
`incident.media`, `incident.both`). Переключатель языка меняет баннер
вместе с остальными **системными** надписями, без повторного вызова API и
без изменения пользовательских публикаций. Разметка имеет `role=status`,
`aria-live=polite` и `hidden` в здоровом состоянии; оформлена в единой
тёмно-золотой дизайн-системе, без навязчивой анимации, с переносом на 360 px.

Состояние нельзя активировать через UI либо пользовательский `POST`.
Оно контролируется только доверенным процессом при старте. Клиентское
предупреждение — лишь объяснение. **Реальные ограничения всегда
применяются сервером**, даже при отключённом JavaScript.

## Измеримая независимая приёмка

`node server-lab/test/r82.incident_banner_cdp.mjs` поднимает четыре
раздельных живых Node/SQLite сервера, открывает настоящим Chromium в
вариантах 1440/390/360 px и проверяет каждый из четырёх health-режимов:
RU → EN, правильный ключ и текст, отсутствие баннера в обычном режиме,
ARIA, отсутствие горизонтальной прокрутки, отсутствие внешних запросов
и исключений JS. На каждом экране сохраняются реальные снимки PNG
в `qa-r82/` для ревью.

Обязательные CI продолжают выполнять R79 и R81 проверки сессий и
выдачи контента, а также старые R60/R65 медиацикл, R64 клавиатуру,
R71/R77 локализацию, R76 multi-tenant и R49 нагрузку. Этот UI-блок не
переписывает права пользователя или модератора.

## Что ещё не готово

Production требует межсерверного состояния, атомарного отключения
CDN/Storage/CDN signed URL, краткого TTL, global cache invalidation,
readiness probes, реальных инцидентных дежурств, независимого теста
восстановления, юридического урегулирования и авторизованного
оператора. Временная лабораторная переменная окружения не заменяет
боевой аварийный выключатель.
