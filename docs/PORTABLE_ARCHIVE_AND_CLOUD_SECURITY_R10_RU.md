# MARCOSA R10 — переносимый архив и защищённая серверная схема

**Срез: 24 октября 2026.** Новая функция R10 работает в публичном статическом прототипе после успешной публикации GitHub Pages. **Доступный Supabase-коннектор вернул пустой список проектов.** Поэтому SQL **не применялся** и настоящие пользовательские аккаунты, серверное сохранение и модерация **не включены**. Contabo, production MARCOSA и Stripe не изменялись.

## 1. Что пользователь получает сейчас

В Creator Engine появился блок «Резервная копия архива»:

1. **Скачать все проекты** — один JSON со всеми сохранёнными редакциями (до 8 проектов, до 15 последних редакций каждого), формат marcosa-local-vault-backup/v1.
2. **Восстановить архив** — проверка размера до 2 МиБ, схемы, проекта, ISO-дат и содержимого каждой версии, предварительный подсчёт новых/совпадающих/конфликтных проектов и запрос подтверждения.
3. Повторный импорт идентичной копии **не создаёт дубликат**. Если идентификатор совпал, но версии расходятся, импорт сохраняет **отдельную копию с новым случайным ID** и не перезаписывает существующую историю.
4. Если вместимости в 8 проектов недостаточно, импорт целиком отклоняется. Восстановление атомарно — одна readwrite-транзакция IndexedDB, без частично добавленных проектов.

Все данные валидируются тем же строгим проверяющим модулем R9. Восстановление не подтверждает авторские права, не выдаёт модераторских разрешений и не публикует материалы.

**Предупреждение:** JSON-файл содержит полный текст историй и **НЕ зашифрован**. Храните его в безопасном месте и не отправляйте посторонним. Браузерная IndexedDB — не облако: при очистке данных сайта записи могут исчезнуть. Экспорт выполняется только по нажатию кнопки, без трекеров и автоматической загрузки на сервер.

## 2. Подготовленный серверный контур — ещё не применён

Файл: infra/supabase/r10_cloud_schema_review_only.sql. Он описывает независимые будущие таблицы:

| Объект | Назначение |
| --- | --- |
| public.marcosa_cloud_projects_r10 | Проекты: собственные записи каждого автора |
| public.marcosa_cloud_revisions_r10 | Неизменяемые текстовые редакции собственного проекта |
| public.marcosa_review_submissions_r10 | Авторские заявки на независимую ручную проверку |
| marcosa_private.marcosa_moderation_decisions_r10 | Решения модераторов только на доверенном сервере, без доступа обычных пользователей |

SQL-проект содержит RLS для всех таблиц, явные разрешения и запреты, сверку владельца через auth.uid(), отдельное исключение анонимных Auth-сессий и составные внешние ключи. У авторов нет прямого разрешения менять прошлые редакции, решения модератора или статус публикации. Серверная схема не содержит браузерного service_role, SECURITY DEFINER и публичного API для публикации.

**Это архитектурная заготовка, а не работающая облачная платформа.** SQL не проверен на настоящем Postgres и не применён к чьей-либо базе. Отдельная модераторская панель, публикационный шлюз, аудит и правовые процессы отсутствуют.

## 3. Что требуется перед настоящим серверным запуском

1. Выбрать существующий либо создать новый *изолированный* Supabase-проект только с согласия владельца на возможные расходы.
2. Проверить настройки Data API, реальную схему, RLS и ограничения ролей перед применением SQL.
3. Прогнать SQL в тестовой базе под двумя разными аккаунтами и проверить запрет чтения чужих проектов, записи чужих редакций, удаления истории и доступа к частной схеме.
4. Получить результаты Supabase Security Advisors, настроить сроки хранения, резервное копирование, права редакторов, аудит и удаление данных.
5. Только затем создавать настоящий frontend с подтверждённой авторизацией, очередью модерации и отдельным контролируемым шлюзом публикации.

Официальные источники: https://supabase.com/docs/guides/database/postgres/row-level-security и https://supabase.com/docs/guides/api/securing-your-api. Актуальность: https://supabase.com/changelog.

## 4. Приёмка

- tests/backup.test.cjs: полный JSON roundtrip, ограничения размера, защита от лишних полей и поддельных approvals, подсчёт конфликтов и лимитов.
- tests/test_cloud_schema_contract.py: только **статический** аудит SQL, не заменяет живого тестирования RLS.
- tools/r9_cdp_smoke.cjs: настоящий Chromium на localhost, desktop и mobile, резервное копирование, удаление, восстановление, пропуск идентичного импорта и сохранение конфликтующей версии отдельно.
- tools/r5_capture_preview.py: скриншоты R10 в компьютерной и мобильной раскладках.
- tools/build_webroot.py: **13** разрешённых публичных файлов и SHA-256 manifest. SQL, ключи и персональные данные не входят в статический релиз.

Результат R10 — работающий перенос локальных авторских архивов и проверяемый проект будущей серверной безопасности без ложных заявлений о запуске Supabase.
