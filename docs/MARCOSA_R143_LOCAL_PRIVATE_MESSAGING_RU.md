# MARCOSA R143 — личные и групповые сообщения в локальной лаборатории

R143 добавляет настоящий двусторонний и групповой чат в существующий `server-lab/`. Это продолжение имеющегося Node.js / SQLite API-контракта, а не отдельная production-соцсеть. Сервер остаётся привязанным к loopback; GitHub Pages, MARCOSA production, Supabase и реальные аккаунты не меняются.

## Пять инженерных частей

1. **Модель бесед:** SQLite-таблицы `conversations`, `conversation_members`, `messages`, `message_reports` и `message_moderation_audit`; каскадные связи и курсорный индекс сообщений.
2. **Запрос личного контакта:** можно отправить первое короткое сообщение незнакомому участнику. Получатель принимает или отклоняет запрос; до принятия отправитель не может прислать ещё одно сообщение. Отклонение удаляет первое сообщение. Получатель может позднее сам начать новый запрос.
3. **Группы и чтение:** участник может создать группу из 3–12 аккаунтов. Входящие беседы видны только участникам, сообщения выдаются порциями по ID, непрочитанные считаются относительно личного курсора чтения.
4. **Безопасность и модерация:** проверки авторизации, членства, same-origin, bilateral block, ограничения частоты и размера, жалобы на сообщения, независимая очередь модератора и журнал скрытия. Freeze останавливает отправку, оставляя чтение, жалобу и отметку прочитанного.
5. **Интерфейс, доступность и переносимость:** RU/EN desktop/mobile inbox, личный запрос и создание группы, thread view, принятие/отклонение, жалоба. Экспорт содержит только беседы текущего пользователя и доступную ему историю; удаление аккаунта удаляет его данные и очищает оставшиеся беседы без участников.

## API

- `POST /api/conversations` с `kind=direct` и `username` создаёт или находит личную беседу; с `kind=group`, `title`, `participants[]` создаёт группу.
- `GET /api/conversations` возвращает только членские беседы, статус запроса, последний текст и непрочитанное количество.
- `GET /api/conversations/:uuid/messages?limit=30&cursor=...` выдаёт до 50 сообщений участнику.
- `POST /api/conversations/:uuid/messages` отправляет текст 1–2000 символов; 60 сообщений в минуту на аккаунт в этой локальной лаборатории.
- `POST /api/conversations/:uuid/read`, `/accept`, `/decline` управляют собственным курсором и состоянием личного запроса.
- `POST /api/messages/:id/report`, `GET /api/mod/message-reports`, `POST /api/mod/messages/:id/hide` реализуют жалобы и ручное решение модератора.

Все новые ответы явно помечают `production:false`, где это требуется API. Нет вложений, шифрования, push, e-mail, доставки после ухода из сессии, автоматической очистки по сроку, коммерческой модерации или гарантии доступности. Не отправляй в лабораторию секретные сведения.

## Проверки и границы

`server-lab/test/r143.messaging.test.mjs` проверяет запрос/принятие/отклонение, повторный контакт, группу, непринадлежащий доступ, блокировку, пагинацию, unread, отчет и скрытие, экспорт, удаление аккаунта, внешний Origin и поведение freeze.

Успешные тесты подтверждают только локальный серверный контракт. Для production всё ещё нужны проверенный Supabase Auth / PostgreSQL RLS, отдельный staging, восстановление реальных данных, миграционный план и независимый выпускной gate. R143 не подключает production и не снимает эти блокировки.
