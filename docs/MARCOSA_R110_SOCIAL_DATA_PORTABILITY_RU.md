# MARCOSA R110 — перенос личных данных Social Core без облака

## Решённая проблема

Отдельный hostname (GitHub Pages сегодня, собственный поддомен в будущем) имеет собственные `localStorage` и `IndexedDB`. Поэтому закладки и короткий черновик страницы Social Core нельзя просто перенести сменой адреса сайта. Данные останутся в браузере на старом происхождении.

**Реализовано:** пользовательский JSON-экспорт и импорт **только избранных карточек и короткого черновика** через настоящую страницу `social.html` (без серверного API).

## Реальные компоненты

- `site/social-transfer.js`: чистые схемы `MARCOSA-SOCIAL-TRANSFER` v1, предел 16 КБ, проверка UUID/идентификаторов четырёх известных карточек, строка черновика не длиннее 700 символов; экспорт и проверяемый импорт.
- `site/social-core.js`: событие `marcosa:social-transfer` обновляет видимые закладки/черновик без перезагрузки.
- `site/social.html`: кнопки «СКАЧАТЬ АРХИВ» и «ВОССТАНОВИТЬ», доступные с клавиатуры, сообщения о результате и приватности.
- `site/marcosa-social-first.css`: тёмный редакционный стиль, мобильная адаптация, фокус для клавиатуры, режим reduced motion.
- `tests/social-transfer.test.cjs`: тесты сериализации, ограничений, подменённого JSON, повторов, XSS-идентификаторов, конфликтов, повреждённого исходного хранилища, ошибок сохранения и реальной интеграции в DOM.
- `tools/build_webroot.py` и CI: новый `social-transfer.js` в публичном allowlist и обязательной проверке сборки, манифест выпуска и публичная SHA-256-проверка теперь включают его автоматически.

## Политика безопасности и сохранности

1. Сохранённый черновик на устройстве **никогда не затирается** черновиком из файла. Если он отличается, интерфейс сообщает о конфликте. Список закладок объединяется без повторов.
2. Если в поле введён несохранённый текст, импорт останавливается до подтверждения пользователя. Некорректные старые данные в `localStorage` запрещено заменять новым архивом.
3. На ошибке записи предпринимается возврат к старому состоянию. Web Storage не предоставляет транзакций, поэтому при полном отказе хранения нельзя обещать абсолютно атомарный откат.
4. Никаких `fetch`, AJAX, CDN, скрытой синхронизации, экспорта на сервер, передачи аккаунтов или преобразования текста в HTML нет.
5. Экспортируемый JSON **не зашифрован**. Не храните в нём пароли/токены и не пересылайте посторонним.
6. Личный многостраничный журнал уже имеет отдельные функции `MARCOSA-journal` экспорта/импорта, а Studio Creator — свой зашифрованный/локальный архив. Новый файл Social Transfer **не включает** эти независимые хранилища и не выдаёт себя за полный бэкап аккаунта.

## Как переносить через отдельные домены

1. На прежнем домене открыть `Social → Перенести личное → СКАЧАТЬ АРХИВ`.
2. Перейти на новый домен с независимым происхождением, открыть `Social → ВОССТАНОВИТЬ`, выбрать сохранённый JSON.
3. Проверить избранные карточки и черновик, отдельно экспортировать/восстановить журнал и проекты, если они используются.
4. Исходные данные не удаляются автоматически и остаются на старом происхождении, пока пользователь сам не решит их удалить.

## Граница production

`marcosa.club` всё ещё отдельная существующая многопользовательская платформа, и никакая миграция авторизации/Supabase не выполнялась. R110 предотвращает потерю **локальных данных статического предпросмотра**, но не претендует на перенос облачных аккаунтов.
