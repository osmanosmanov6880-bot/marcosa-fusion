# MARCOSA R109 — независимый адрес предпросмотра: DNS / HTTPS / безопасность

## Факты

- GitHub Pages уже размещает статическую MARCOSA на **отдельном происхождении**: `https://osmanosmanov6880-bot.github.io/marcosa-fusion/`. Полный публичный SHA-256 readback 62/62 подтверждён.
- Старое приложение `marcosa.club` использует собственные модули Auth и Supabase; R108 выявил обращения к `localStorage` (17), `indexedDB` (12), `sessionStorage` (1), а также 5 root-relative ссылок/запросов в подготовленных фильмах.
- Размещение нового JS по `marcosa.club/network-os/` создаёт **общий Web Storage origin** со старым сайтом. R105 умеет технически разместить маршрут, но не доказывает безопасность учётных записей.

## Предпочтительный путь

1. **Пока сохранять отдельный GitHub Pages домен.** Новый продукт публично доступен, CI сверяет HTTPS-содержимое, старый сайт не затронут.
2. Дополнительно можно подготовить отдельный `preview.marcosa.club` с правильным DNS, отдельным TLS, отдельной конфигурацией веб-сервера и аудитом cookie scope. Отдельный hostname изолирует `localStorage` и `IndexedDB`, но **не гарантирует** изоляцию cookies с `Domain=.marcosa.club`. Предпочтительно не переносить сессии основной платформы на предпросмотр.
3. Не считать домен готовым, пока независимо не проверены публичные DNS, корректная цепочка TLS с сертификатом именно для hostname, возвращаемый ответ и отсутствие перекрёстной авторизации.
4. Любое изменение Nginx/DNS/производственной авторизации требует отдельной root-admin процедуры, предварительной копии и проверки отката.

## Что делает R109

`tools/audit_preview_hostname.py` проверяет **только публичные** DNS-ответы для `preview.marcosa.club`. Если IPv4 не совпадает с независимо закреплённым адресом Contabo `169.58.48.38`, дальнейший TLS-запрос на неизвестный адрес не выполняется. Если DNS соответствует, идёт TLS-подключение к **закреплённому IP** с проверкой сертификата для имени `preview.marcosa.club`, затем один запрос `HEAD /`. Никаких ключей, cookie, паролей, пользовательских данных, SSH-доступов или записей в Nginx не применяется.

`.github/workflows/marcosa-r109-origin-readiness.yml` запускает проверки на PR/main и повторный **ежедневный read-only** мониторинг DNS/TLS. Даже если DNS/TLS проходит, `productionCutoverAuthorized:false`, так как установка приложения, безопасность cookie и Auth отдельно не проверены.

Отчёт сохраняется артефактом; статусы `dnsHasIntendedVps`, `validHostnameCertificate`, `httpStatus` и `previewHostnameReady` выражают исключительно техническую доступность.

## Критерий завершения

Выпуск последней GitHub Pages версии является подтверждённым публичным статическим предпросмотром. Замена старой многопользовательской MARCOSA в этом выпуске **не производится**. Технически готовый поддомен и отсутствие пересечений авторизации — два отдельных обязательных критерия будущей интеграции.
