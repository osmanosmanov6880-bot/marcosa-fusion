# MARCOSA R75 — PostgreSQL: версия PNG и заявление автора как необходимое условие публикации

**Reference-only SQL + живые испытания в disposable PostgreSQL 17.** Прямого доступа к Supabase Storage или Auth нет; никакой проект и производство не изменяются.

## Изменение по сравнению с R61

R61 прежде считал изображение подходящим для выдачи, если World публичен, PNG нормализован, а независимый модератор имеет текущие полномочия. R75 **ужесточает приватное представление** `marcosa_private.world_cover_delivery_ready`: теперь публикация возможна только при наличии подтверждения владельцем **точного текущего SHA-256** файла.

Для этого добавлена `marcosa_private.world_cover_rights_claims` с FK на закрытые метаданные изображения. Записи содержат owner_id, конкретный digest, `rights-v1` и время заявления. Автор не может самостоятельно создавать/подменять записи напрямую через открытую клиентскую Data API: таблица в приватной схеме, RLS включён, права клиентских ролей запрещены. Реальный backend после проверки сессии и явного согласия пользователя должен вставлять эти факты через доверенный сервер. Обновление существующей строки запрещено SQL-триггером — для нового PNG создаётся новое утверждение, история старых SHA сохраняется до удаления World/Media по FK.

## Правила eligibility

Одновременно должны быть истинны: публичный World; соответствие World и owner_id; PNG статус `approved`; нормализация; независимый действующий модератор в **app metadata**, а не user-editable metadata; и правообладатель `owner_id` с подтверждённой **текущей версией digest**. Установка статуса approved не обходит проверку версии. При замене PNG, снятии роли модератора, переводе World в private или удалении прав нового digest выдача через модель eligibility прекращается.

Это не публичный signed URL и не разрешение отдавать Storage bytes пользователю: реальный backend обязан проверить текущую блокировку зрителя, expiry подписанной ссылки, приватный бакет и подтверждённую модерацию.

## Проверка

`tests/postgres/110_private_rights_delivery.sql` работает только в PostgreSQL 17 CI после R30–R72. Проверяет RLS/no client grants, запрещённую запись чужого владельца или неверного digest, скрытие прежних approved обложек без нового заявления, положительное разрешение при SHA-декларации, отсутствие публикации после замены, восстановление eligibility после НОВОГО заявления, историю двух версий, отзыв роли модератора и каскадное удаление.

Это **не юридическое доказательство авторского права**. Наличие заявления не подтверждает лицензию, model release, согласие людей и отсутствие запрещённого контента. Для мирового выпуска остаются обязательными внешняя проверка лицензий, notice-and-takedown, реальные Trust & Safety, отдельный Supabase project/Storage и независимый security/legal go/no-go по Issue #55.

Поскольку новый PG view ужесточает прежние правила, настоящую миграцию разрешается выполнять только на одобренном STAGING с проверкой всех существующих обложек, rollback, бэкапом и тестом нескольких настоящих JWT. Нельзя автоматически считать старые approved картинки правообладательски подтверждёнными.
