# MARCOSA R78 — единое условие публичной доступности обложки на всех маршрутах

**Сфера:** локальная Node22/SQLite лаборатория. Не STAGING/Supabase Production.

## Исправленная ошибка

После R74 серверные PNG-байты и OpenGraph уже строго требовали утверждение автора на текущий SHA-256 PNG. Но JSON каталога `GET /api/worlds`, поиск `GET /api/discover` и конкретный `GET /api/worlds/:slug` продолжали возвращать `hasCover=true` для старого approved-изображения **без** действительного утверждения автора. Это создавало «сломанные» миниатюры в приложении и несогласованные сигналы о публичной публикации.

R78 меняет все три серверных SQL-запроса: `hasCover=true` допустим только при одновременно действующем approved PNG, независимом модераторе с актуальной ролью и подходящей записи `world_cover_rights`, у которой owner совпадает с World, заявление `rights-v1` и `asset_sha256` равен **вычисленному SHA-256 самого сохраняемого BLOB**.

В Node 22 SQLite нет встроенной функции SHA-256: для этого однажды при открытии локальной БД регистрируется deterministic `marcosa_sha256(blob)` через поддерживаемый `DatabaseSync.function`. Она проверяет двоичный `Uint8Array` и возвращает SHA-256. Это никак не выдаёт пользователю приватную историю заявлений и не загружает файлы в интернет.

## Приёмка реальными HTTP-запросами

Продолжен `server-lab/test/r68.world_pages.test.mjs`: реальный Node 22/SQLite с двумя пользователями и независимым модератором, 36 миров сверх первой страницы каталога, оригинальные PNG BLOB. Новые проверки сравнивают пять маршрутов: бинарный URL, SSR OpenGraph, JSON World, Search и первую страницу каталога. Имеющиеся approved обложки без прав скрыты **везде**; запись актуального SHA включает выдачу; подмена SHA выключает флаг; отзыв роли модератора тоже выключает выдачу. Старые тесты XSS, блокировки и noindex остаются.

Три обязательных GitHub Actions на точном коммите: социальный сервер/Chromium, World Builder, R49 локальная нагрузка. **Без всех зелёных CI не объединять.**

## Ограничения

Для реального Supabase production аналогичный gate должен обеспечиваться доверенным backend с текущим Auth/JWT, private Storage и RLS, не SQL-хешированием всего содержимого `storage.objects`. Документированное заявление правообладателя не равно юридически подтверждённой лицензии. Публичный выпуск по Issue #55 остаётся заблокирован.
