# MARCOSA R119 — реальный Node/SQLite social API на VPS, только закрытая временная лаборатория

## Для чего этот этап

Статический GitHub Pages и R117 подтверждают **публичную графическую оболочку**, R118 проверяет границу с существующей production-платформой. В `server-lab/` уже написан настоящий Node.js API для аккаунтов, миров, черновиков, подписок и модерации. Но тесты этого API прежде выполнялись **только на GitHub runner/localhost**.

R119 запускает **существующий**, а не имитированный сервер MARCOSA на настоящем Contabo **однократно**, без публичного порта, без production-данных и без долгоживущего сервиса.

## Что именно делается

1. Событие запуска — успешный `R118` на точном коммите `main` с реальной проверкой совместимости, либо ручной запуск на `main` для отдельной диагностики. На PR выполняются **только локальные** тесты без SSH.
2. Независимо повторяется `R117=PASS` на **том же SHA**, проверяется закреплённый ключ SSH-сервера и публичный fingerprint **не-root** ключа пользователя `marcosa-deploy`. `StrictHostKeyChecking=yes`.
3. На VPS передаётся только проверенный `server-lab/` и `ops/r119_social_smoke.mjs` во **временный каталог с правами владельца** в домашней папке `marcosa-deploy`. Никаких секретов, пользовательских бэкапов, ключей сайта и баз данных в архиве нет. Symlink в исходном дереве запрещён.
4. Скрипт требует Node.js 22.13+, импортирует настоящий `createApp` из `server-lab/server.mjs` с SQLite `:memory:`, запускает API на `127.0.0.1` на свободном эфемерном порту. Если Node отсутствует, запуск **завершается BLOCKED**; установки через `sudo` или скачивания Node нет.
5. Через **настоящие HTTP-запросы по loopback** проверяются: `/api/health`, запрет Host-rebinding, отказ от постороннего Origin, запрет гостевой выгрузки, два синтетических аккаунта, реальные HTTP sessions, приватность двух Worlds, отказ в записи чужого World, черновик против публичного поста, частный экспорт, удаление аккаунта, отзыв его сессии и целостность SQLite.
6. В конце `app.close()` закрывает HTTP-порт и соединение SQLite, оболочка VPS удаляет только созданную временную папку. В GitHub сохраняется **только** машинный `PASS` с SHA и булевыми проверками. Пароли, токены, cookie, SQL-файлы с людьми и сырая база никогда не выгружаются.

## Чего эта проверка НЕ доказывает

- Никакой production Auth/JWT/MFA, PostgreSQL/RLS, Supabase Storage или реальных аккаунтов.
- Никакой публичной HTTPS-доступности многопользовательского API: сервер доступен только локально на самом VPS.
- Никакой защиты от полномасштабного DDoS, производственных RTO/RPO, юридического допуска, действующих платежей или реально согласившейся когорты.
- Нет смены DNS, Nginx, root webroot, существующих `/opt/marcosa/current`, сессий, пользователей и баз.

Даже успешный `R119_ACTUAL_VPS_EPHEMERAL_SOCIAL_API=PASS` **не даёт права публиковать социальный API наружу** и не снимает `Issue #55`.

## Файлы и приёмка

- `ops/r119_social_smoke.mjs`: рабочий HTTP-клиент/проверяющий поверх оригинального Node+SQLite сервера.
- `tests/r119_vps_social_smoke.test.mjs`: действительный offline HTTP+SQLite тест и верификация отказов.
- `.github/workflows/marcosa-r119-vps-social-smoke.yml`: ограниченный, защищённый, SSH-запуск только после R118.
- Запуски [R119 в GitHub Actions](https://github.com/osmanosmanov6880-bot/marcosa-fusion/actions/workflows/marcosa-r119-vps-social-smoke.yml).

**Важный нюанс:** доказать, что конкретный Node runtime работает на VPS, возможно только после выполнения SSH-job. Успешная проверка в GitHub runner доказывает код, но не установленную Node 22 на Contabo.
