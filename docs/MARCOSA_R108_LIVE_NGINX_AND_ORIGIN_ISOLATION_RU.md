## Новые независимые испытания

1. `tests/test_r108_nginx_route.py` использует **настоящий Nginx** внутри временной папки и на свободном `127.0.0.1` порту. В тест подставляется именно `NGINX_SNIPPET` из действительного установщика. Проверяются: старая главная и API не затронуты, `/network-os` делает 308, `/network-os/` и JS/CSS правильно отдаются по MIME, несуществующие файлы дают 404, атомарная смена canary-указателя не меняет старый сайт.
2. `tools/audit_canary_origin.py` просматривает только опубликованные исходные HTML/JS/CSS и составляет **обезличенный отчёт** о корневых URL и использованиях браузерных storage API. Содержимое локального хранилища и прежнего сайта не читается.
3. `.github/workflows/marcosa-r108-nginx-origin-audit.yml` создаёт новый job на изолированном GitHub Runner, использует реальный Nginx, выполняет тесты и сохраняет JSON-отчёт; не подключается к Contabo и не меняет production.

## Существенный риск

Новая версия использует `localStorage` и `indexedDB` — в частности, локальный дневник, черновики и хранилище проектов. Если подключить новый JS по адресу **`https://marcosa.club/network-os/`**, у него будет то же происхождение (origin), что и у уже работающих сессий и хранилищ основного `marcosa.club`. URL-папка **не** является изоляцией данных браузера. Аудит текущего приватного Auth-приложения ещё не сделан. Следовательно:

- Даже идеальный 62/62 HTTPS или Nginx smoke **не доказывает** безопасность размещения дополнительного JS под тем же origin.
- Не следует делать автоматический production cutover лишь потому, что новый маршрут технически свободен.
- Для полноценного нового продукта лучше использовать **отдельное HTTPS-происхождение**, например выделенный поддомен с проверенными DNS и TLS, либо пока сохранять GitHub Pages как отдельный предпросмотр.
- Если основной домен когда-либо будет объединён с новым приложением, сперва нужны аудит авторизации, cookie, localStorage, IndexedDB, CSP, CSRF, Supabase/RLS и тесты миграции.

Именно поэтому `R108` возвращает `safeToEnableSameOriginProductionAutomatically:false` и `productionCutoverAuthorized:false`, даже если все Nginx-тесты прошли.
