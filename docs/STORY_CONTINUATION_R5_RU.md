# MARCOSA R5 — Story Continuation Pilot

**Критический этап мастер-плана:** первый настоящий технический сценарий «интересный сюжет → добровольное решение зрителя → тематическая карточка проекта». В этой реализации нет подключения к реальным фильмам, личным Worlds, регистрациям или Supabase. Это функциональный публичный пилот, позволяющий проверить механику без риска для production.

## 1. Что реализовано

- \`site/stories.html\` — отдельная доступная страница, путь \`./stories.html\`, встроенный вход с главной MARCOSA.
- \`site/stories.js\` — самостоятельный детерминированный движок: **3 вымышленных сценария × 2 бинарных решения = 12 объяснимых финалов**; RU / EN / 中文.
- \`site/stories.css\` — оригинальные премиальные CSS-сцены с клавиатурной навигацией и fallback для \`prefers-reduced-motion\`. WebGL R4 продолжает обслуживать главную страницу независимо.
- \`site/network.js\` — только **белый список** deep-link маршрутов:
  - \`index.html#network-product=proofos\` открывает в каталоге карточку конкретного проекта.
  - \`index.html#network-campaign=signal-worlds\` открывает локальный черновик собственного промо.
  - Неизвестные slugs, запросы и произвольные внешние URL отклоняются.
- Brand Studio — локальный структурированный **\`marcosa-branded-story-brief/v1\`** с указанием аудитории, проблемы, сюжета, продукта, добровольного CTA и условий публикации. Экспортируется только JSON, не отправляется на сервер.
- Local QA — строго **opt-in**, in-memory счётчики и журнал для данной вкладки. После отказа от записи очищается. Никаких user ID, IP, отпечатков браузера, cookie, localStorage, аналитики или фоновых запросов.

### Сценарии

| Демонстрация | Что проверяет | Тематические проекты |
|---|---|---|
| «Последняя минута» | ожидание, очереди, прозрачность процессов | TIMELESS, WAITOS, OpsPilot |
| «Сигнал истины» | проверки заявлений, согласование рекламы | ProofOS, ADVERSE JUDGE, IntentGraph Cosmic ONE |
| «Мир после титров» | продолжение интерактивной истории, добровольные бренд-сюжеты | SIGNAL WORLDS, PROTOCOL ZERO, IMPOSSIBLE AI, Impossible Ventures |

**Все три — вымышленные художественные примеры**, а не заявленные владельцем реальные опубликованные сайты. 43 слота фильмов по-прежнему требуют инвентаризации и проверки прав.

## 2. Trust by design

- Только перечисленные выше известные source-backed продукты. Их поле \`live:false\` не меняется.
- Рекомендация — простое правило от **двух явных ответов**, а не «ИИ знает намерения человека».
- На финале объясняется, почему предложен конкретный проект. Нет скрытой подмены контента рекламой.
- Переход — **добровольный**, по кнопке после финала. Автоматических переходов нет.
- На странице нет API бэкенда, платежей, email-сбора или подписки.
- Бриф обязателен с подтверждением использования материалов и раскрытием спонсорства. Это только **самостоятельная декларация**, не доказательство лицензии.
- Состояние \`publication_state:not_published\`, \`rights_independently_verified:false\`, \`product_public_service_verified:false\`; никаких фиктивных отзывов, продаж, владельцев или просмотров.

## 3. Опциональные QA-события

Текущая схема \`marcosa-story-qa/v1\` содержит только:
\`film_started\`, \`choice_selected\`, \`film_completed\`, \`recommendation_rendered\`, \`recommendation_clicked\`.

В одном отчёте **только** \`type\`, \`story_id\`, \`stage\` и при выборе \`product_slug\`. Нет сетевой отправки. Эти данные являются отчётом ручного тестировщика в одной вкладке; их запрещено трактовать как уникальных зрителей, реальную конверсию, рекламные показы или доказательство дохода. Report скачивается только после ручного включения записи; при отключении журнал очищается.

## 4. Локальная проверка

Из корня репозитория:
\`\`\`bash
python3 -m http.server 8765 -d site
\`\`\`
Открыть \`http://127.0.0.1:8765/\` → **EXPERIENCE THE STORIES**. Открыть каждую из трёх историй, пройти оба выбора, затем просмотреть рекомендации и перейти к карточке товара в каталоге.

Тесты:
\`\`\`bash
node --test tests/film_kit.test.cjs tests/immersive.test.cjs tests/r4_graphics.test.cjs tests/stories.test.cjs
python -m unittest discover -s tests -q
python tools/audit_public_source.py
python tools/build_webroot.py
python tools/r4_browser_smoke.py
python tools/r5_browser_smoke.py

Browser QA на GitHub Actions проверяет JS и работу интерактивных кнопок. Скриншоты из CI относятся к браузерному рендеру на hosted runner, а не к пользовательской видеокарте.

## 5. Критерий допуска к коммерческому пилоту

Нынешний технический MVP **ещё не коммерчески валидирован**. Для настоящих трёх фильмов:
1. Получить три действительных URL и подтверждённые права на контент, домены и использование брендов.
2. Проверить реальные финальные сцены и выбрать ненавязчивый CTA после окончания.
3. Проверить живые пути на MARCOSA Worlds / продукты в отдельной staging-копии, не заменяя production из статического preview.
4. Изучить разрешения и удаление данных, RLS, экспорт/откат, мобильную доступность и performance.
5. Исследовать честный baseline с реальными участниками; отличать технические события от людей, регистраций и платежей.
6. Создать подписываемое предложение по **услуге производства интерактивного брендированного сюжета**, с отдельным расчётом стоимости. Не продавать недоказанный CPM/охват.

### Gate

**INVEST / VALIDATE:** механизм рекомендаций и бриф можно показывать как безопасную техническую демонстрацию. **HOLD:** публикация на настоящих киносайтах, сбор данных, биллинг, регистрация Worlds и любые заявления о количестве зрителей, пока нет прав и инфраструктуры. Сохранение независимости приложений — обязательное ограничение.

## 6. Что дальше

- Проверить R5 локально и на реальном мобильном устройстве (включая навигацию клавиатурой, контрастность, отсутствие horizontal scroll).
- Отметить реальные три разрешённых фильма; затем подготовить первый staging-коннектор с ручным approve/rollback.
- Сверить production SHA, Contabo VPS map, Supabase миграции и RLS до любого production integration.
- После 5–10 интервью с владельцами брендов — дополнить бриф коммерческим workflow без выдуманных контрактов.

**Важно:** главная графическая среда R4 и весь каталог 16 проектов остаются работоспособными; R5 не изменяет пользовательские аккаунты, Worlds, базу данных и живой сервер.
