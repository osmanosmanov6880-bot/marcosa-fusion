# MARCOSA R69 — измеримый операционный контроль модерации

**Статус области:** настоящая локальная Node 22 / SQLite платформа. Нет production SLA, юридических сроков, глобального трафика или опубликованного мониторинга.

## Что работает

Новый приватный `GET /api/mod/queue-health` возвращает агрегированное состояние **семи настоящих очередей**: новые обложки, жалобы на опубликованные обложки, апелляции по обложкам, жалобы на публикации, жалобы на комментарии, апелляции на контент и рекламные заявки на проверке. Источник — существующие SQLite-таблицы, не файлы с фиктивными цифрами.

Для каждой очереди из фактических записей вычисляются `pending`, `overdue` и `oldestAgeHours`. В интерфейсе в кабинете независимого модератора показаны реальные значения и кнопка ручного обновления. Исходные тексты, почты, идентификаторы заявителей, содержимое публикаций, пароли, IP и изображение **не включаются в сводку**.

**Внутренние лабораторные ориентиры:** 24 часа для обложек и жалоб, 72 часа для апелляций и рекламных заявок. Считается открытая запись, созданная или обновлённая не позднее момента `now() - targetHours`. Это диагностические ориентиры, а не обещание правовой защиты, срок исполнения по договору или реальный SLO.

В сводке `overdueRate=null`, если нет открытых записей. Нельзя рисовать 0% просрочек при отсутствующем знаменателе. При нулевых очередях `oldestAgeHours=null`. Фактическое время UTC берётся из тестируемого серверного часовщика.

## Разграничение доступа

- Гость получает HTTP 401.
- Пользователь без роли модератора получает HTTP 403.
- После отзыва роли действующая сессия перестаёт видеть сводку: каждый запрос заново проверяет текущую роль на сервере.
- Ответ содержит только агрегаты и всегда обозначен `production:false`. Никаких отдельного внешнего endpoint, webhooks, телеметрии третьим сторонам или изменения JWT.

## Независимая приёмка

`node --test server-lab/test/r69.moderation_operations.test.mjs`: настоящий HTTP сервер, 3 аккаунта, 7 фактических записей SQLite с контролируемыми временными метками, математически проверенные знаменатель и просрочки, закрытие каждой очереди, отзыв роли, отсутствие персональной информации и проверка FK.

Существующий браузерный R65 E2E также проверяет R69 на desktop и телефоне: **1 реальная жалоба** отображается в агрегате, после независимого удаления публичного PNG показатель становится **0**. Прилагаются реальные снимки до и после решения.

Полная production-реализация дополнительно потребует нескольких модераторов, распределения назначений, legal response deadlines по юрисдикциям, дежурства, независимого аудита сроков и настоящей системы инцидентов. R69 не отменяет gate Issue #55.
