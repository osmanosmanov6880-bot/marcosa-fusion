- Отдельный workflow STAGING **40085254729**: `build` — success, архив `marcosa-site.tar.gz` успешно прошёл `sha256sum -c`.
- `deploy_staging` — **failure** на шаге `Diagnose SSH and confirm remote staging readiness (read-only)`.
- Точный диагноз: `Pinned host key mismatch; verify independently in the Contabo console, do not bypass verification.`
- Секреты host/user/key/known_hosts предоставлены Actions, но их подлинность и безопасность **не подтверждены**. Никакой загрузки или активации на STAGING не произошло.

## Почему остановили публикацию
Ключ хоста — криптографическая идентичность SSH-сервера. Несовпадение может означать переустановку ОС, смену сервера/IP, неверно записанный ключ либо атаку посредника. Нельзя принимать новый ключ только потому, что его возвращает `ssh-keyscan`; это не независимая проверка.

## Безопасная процедура восстановления для администратора
1. Открыть **свою** панель Contabo, определить точный сервер по инвентарному номеру и сверить hostname/IP с `MARCOSA_STAGING_HOST` в защищённой конфигурации репозитория.
2. Через доверенную консоль провайдера или другой заранее проверенный защищённый канал прочитать текущие публичные SSH host keys **на самом сервере** (например, `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`). Не копировать приватные `ssh_host_*_key` никуда.
3. Проверить у ответственного администратора, **почему** изменился ключ: была ли подтверждённая переустановка, ротация или перенос. При неизвестной причине — сохранить блокировку, проверить учётные записи и сетевые изменения.
4. Только после независимого подтверждения актуального публичного host key подготовить корректную запись `known_hosts` с соответствующими hostname/IP и портом. Обновить **только** GitHub Actions secret `MARCOSA_SSH_KNOWN_HOSTS` через защищённые настройки среды `marcosa-staging`; приватный SSH ключ и содержимое других секретов не выводить в чат или логи.
5. Запустить STAGING workflow вручную из ветки `main` и проверить, что шаг SSH diagnosis успешен, а журнал подтверждает `STAGING_VERIFIED_RELEASE=<SHA>`. Сверить SHA с `main`. Убедиться, что активирован только каталог `$HOME/marcosa-staging`, а production и Nginx не затронуты.

## Чего **не делать**
- Не использовать `StrictHostKeyChecking=no`, `UserKnownHostsFile=/dev/null`, пустой `known_hosts` или безусловный `ssh-keyscan >> known_hosts`.
- Не удалять проверку SSH fingerprint из `scripts/diagnose-staging-ssh.sh`.
- Не выдавать публичный GitHub Pages за подтверждённый отдельный сервер STAGING.
- Не просить прислать сюда приватный ключ, root-пароль, содержимое токенов или secrets.

## Статус работы
**Public R27: published. Isolated STAGING: blocked by host identity verification.** Автоматически исправить этот факт правками CSS/JS или повторными деплоями нельзя. Исправление зависит от проверки доверенного источника у владельца сервера.
