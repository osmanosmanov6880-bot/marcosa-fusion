# MARCOSA R49 — настоящая локальная нагрузочная и приватностная проверка

В R49 добавлен запускаемый `ops/local-read-load.mjs`, который **действительно** создаёт в памяти SQLite профиль по одноразовому локальному лабораторному приглашению, публикует 8 реальных тестовых записей и исполняет параллельные HTTP-запросы к действующему localhost-серверу.

## Что проверяется

- Публичные маршруты: health, каталог Worlds, поиск, публичная лента и обсуждения.
- Под авторизованной сессией: creator insights, onboarding и личные сохранения.
- Текущие заголовки безопасности, обязательный статус 401 у гостя при обращении к персональной коллекции.
- Реальная очередь 480 GET-запросов при конкурентности 12 (настраивается), с подсчётом статусов, p50/p95/p99 и длительности.
- Ни одного внешнего запроса, нового провайдера, analytics SDK, password token или пользовательских данных. Система отвечает настоящими данными локального сервера.
- Защита CI от слишком агрессивных параметров: максимум 1500 запросов и 32 клиента за один прогон.
- На все маршруты распространяется fail-closed: ошибка HTTP или перегрузка p95 над лабораторным бюджетом 1500 ms проваливает сборку.

## Что означает результат

Артефакт `qa-r49/local-read-load.json` хранит число выполненных запросов, фактически измеренные задержки и ошибки в **этой** GitHub Actions машине. Он не содержит и не доказывает реальные показатели продакшна, вместимость дата-центра, DAU, D7/D30, GPU, рекламные показы, платёжные транзакции или юридическую готовность.

Локальный load QA не даёт разрешения открывать сервер наружу: `server-lab` по-прежнему слушает только loopback и остаётся изолирован от публичного Pages.

## Самостоятельный запуск

Из корня репозитория с Node.js 22:

```sh
node --test ops/test/local-read-load.test.mjs
node ops/local-read-load.mjs
cat qa-r49/local-read-load.json
```

Можно задать `MARCOSA_LOAD_READS=480`, `MARCOSA_LOAD_CONCURRENCY=12`, `MARCOSA_LOAD_P95_BUDGET_MS=1500`, не превышая лимиты. Новая GitHub Actions `marcosa-r49-local-load.yml` запускает автотест и настоящий полный замер, выгружает машинный JSON; не деплоит сервис.

## Следующая производственная приёмка

Когда владелец предоставит реальный, проверенный STAGING и Supabase project, повторить замеры на изолированной инфраструктуре по согласованному профилю нагрузки, включая транзакционные записи и потери пакетов. Отдельно нужны полный load/rate-limit/anti-DDoS тест, восстановление БД, реальные JWT/RLS, независимый security audit и наблюдение за согласившейся когортой пользователей.

Подтверждённые внешние блокировки и документы фиксируются в [#55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55). Подменять отсутствие инфраструктуры искусственным "миллионом пользователей" запрещено.
