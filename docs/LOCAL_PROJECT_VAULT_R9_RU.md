# MARCOSA R9 — Local Project Vault & Manual Review Handoff

Дата среза: 23 октября 2026. **Реализовано в исходниках публичного статического прототипа.** Доступность публичной версии проверяется отдельно успешным GitHub Actions Pages release. Оригинальная авторизованная MARCOSA, Contabo, Supabase, Stripe и чужие фильм-сайты не меняются.

## Что пользователь действительно может сделать

1. Открыть Creator Engine и закончить сюжет с двумя выборами и четырьмя финалами (прежний R8).
2. В новом разделе **«Локальный архив проектов»** дать проекту название, оставить примечание и нажать **«Сохранить новую версию»**.
3. Создать до 8 независимых проектов на устройстве. В каждом хранить до **15 последних** редакций. Счётчик версий монотонный: при достижении лимита первая редакция удаляется из локального архива, номер версии не сбрасывается.
4. Открыть любой сохранённый проект. Выбрать версию, сравнить её с предыдущей по изменённым полям, восстановить её в редактор и **сохранить как следующую новую версию**, не переписывая прежние редакции.
5. Проверить четыре контрольных пункта (авторство, обозначение спонсорства, редактура всех четырёх концовок, отсутствие приватных данных) и скачать **JSON-пакет для независимой ручной модерации**.
6. Удалить один проект вместе со всеми его локальными редакциями через подтверждение удаления.

Сохранение **только вручную** через браузерный IndexedDB. Автосохранения, облачного аккаунта, отправки данных серверу, платёжной системы, публикации в открытом каталоге и отслеживания аудитории нет. Редактирование исходных R8 JSON-файлов остаётся доступным и без IndexedDB.

## Безопасность и честный статус

- **Этот архив не является резервным облаком**. Сохранения относятся к тому же origin/браузерному профилю и могут исчезнуть при очистке данных сайта, в приватном режиме, при смене устройства или сбое диска. Хранить личные сведения или коммерческие тайны на общем компьютере не рекомендуется. Автошифрование приложения не реализовано.
- Для резервной копии скачивайте отдельно JSON в Creator Engine. Пакет для модерации содержит **полный текст истории** — не отправляйте его незнакомым лицам.
- Каждый R9 снимок данных проходит строгий R8 whitelist, ограничения размеров полей; флаги author rights/advertising consent сбрасываются перед локальным сохранением и при восстановлении, чтобы не наследовать давно устаревшее согласие.
- Объект R9 локального проекта: marcosa-local-workspace/v1, ключ — криптографически случайный UUID, дата ISO 8601, список версий, каждое значение отдельный нормализованный снимок. Данные удаляются по отдельной явной команде.
- Контроль конфликтов: если другая вкладка успела записать следующую версию, пользователь не может незаметно затереть её своим сохранением; ему предлагается сначала открыть обновлённый проект. Запись версии в IndexedDB выполняется в одной транзакции.
- Данные не вставляются как HTML: используется только textContent. Незнакомые свойства / статусы published и manual_approval:true отклоняются.
- Код записи версии не вызывает fetch, cookies, tracking beacons, WebSocket или user analytics.

## Review packet: что подтверждено, а что нет

Схема marcosa-review-packet/v1, статус **prepared_for_manual_review**, publication_state: not_published. Поля: ID локального проекта, номер и время последней сохранённой версии, дата подготовки, четыре **самодекларации автора**, текст истории, обязательные проверки.

Независимые флаги всегда **ложные**:

- rights_independently_verified:false
- editorially_approved:false
- security_verified:false
- approved_for_publication:false

Скачивание **не отправляет** файл, не регистрирует заявку, не включает монетизацию и не публикует историю. Название «пакет на ручную модерацию» означает техническую подготовку материала к реальной работе модератора, а не существование подключённой редакции.

Кнопка экспорта блокируется, пока:
- не сохранена актуальная версия;
- текущий текст в редакторе отличается от последнего снимка;
- не отмечены все четыре пункта чек-листа.

После экспорта чек-лист автоматически сбрасывается. При восстановлении старой версии требуется сохранить её заново как следующую актуальную редакцию.

## Проверка перед слиянием

- tests/vault.test.cjs: неизменяемость и лимиты редакций, последовательность версий, обнаружение конфликта другой вкладки, строгая схема, отсутствие фальшивых approvals, пакет проверки, локализация и HTML controls.
- tools/r5_browser_smoke.py: **реальная IndexedDB** в Chromium с изолированным localhost, два экземпляра теста (1440×900 и 390×844): 1-я и 2-я редакции, сравнение, восстановление, новая версия, чек-лист, экспорт, перечитывание данных из базы, удаление.
- tools/r5_capture_preview.py: две дополнительные реальные картинки раздела R9 в настольном и мобильном виде.
- tools/build_webroot.py: фиксированный allowlist из **12** публичных файлов и SHA-256 manifest.
- Полный прежний набор R3/R4/R5/R7/R8 тестов должен остаться зелёным.
- GitHub Pages выпускает R9 только после успешного CI. SSH staging на Contabo — отдельный процесс с подтверждённым pin хоста; пока подтверждение не совпадает, развёртывание останавливается до передачи файлов.

## Дальше к настоящему production

Для общего каталога авторов, совместного редактирования, устойчивого хранения, договоров и фактической публикации потребуются отдельные серверные API, авторизация и роли, подтверждение прав, модераторская очередь, резервное копирование, защита данных, RLS/ACL, наблюдаемость, антиспам, права на домены, контролируемые публикационные релизы и rollback. Ничего из этого **не следует** считать реализованным в R9.
