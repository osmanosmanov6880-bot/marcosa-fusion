# MARCOSA R87 — доступные RU/EN формы и ошибки без потери данных

**Текущая сфера:** локальная реальная Node.js 22/SQLite лаборатория MARCOSA.
Это измеримый отдельный блок международного качества, не полное
подтверждение WCAG 2.2 AA на устройствах пользователей.

## Выполненная функциональность

Когда встроенная HTML5 constraint validation обнаруживает неправильную форму,
пользователь получает системный, доступный, локализованный текст ошибки в
самой форме: `role=alert`, `tabindex=-1`, `hidden=false`. Все
неверные `input/select/textarea` получают `aria-invalid=true` и ссылку
`aria-describedby` на сообщение. Фокус перемещается к **первому неверному
полю**. После исправления текста либо переключения checkbox/select результаты
обновляются без повторной отправки: правильные поля очищаются от старого
`aria-invalid`, а полностью исправленная форма убирает предупреждение.

Текст формы переводится RU/EN через проверенный каталог системных фраз.
Изменение языка обновляет сообщение, при этом **не переводит и не изменяет**
пользовательские публикации, имена, ввод пароля и необработанные данные.
Системное предупреждение создаётся через `textContent`, а не `innerHTML`.
Серверное ограничение длины, прав, роли и владения при этом не меняется.

Поведение применяется также к динамическим HTML-формам: обработчики
`invalid` / `input` / `change` делегированы на `document` с
обязательной проверкой `event.target.form`. Новый отдельный summary
создаётся только для действительно неверной формы. Другие формы страницы
не получают лишние предупреждения. Нет tracking / третьих сторон /
рекламных запросов / нового сбора персональных данных.

Обновлённая тёмная дизайн-система сохраняет высокий контраст статусов,
видимую рамку неверного поля и 360 px мобильное размещение; поддерживается
режим `prefers-contrast: more`.

## Проверенная приёмка

`node server-lab/test/r87.form_validation_cdp.mjs` запускает
**настоящий Chromium и реальный HTTP/SQLite сервер**:

- 1440×900, 390×844, 360×740;
- invalid login без отправки HTTP-запроса, фокус на email;
- работа `role=alert`, `aria-invalid`, `aria-describedby`;
- переключение RU→EN с переводом ошибки;
- исправление email/password, после которого сообщение скрывается;
- независимая неверная форма регистрации, фокус на inviteCode;
- отсутствие боковой прокрутки, посторонних HTTP-запросов и JS-исключений;
- реальные скриншоты RU/EN для независимого ревью в `qa-r87/`.

Существующие R64 keyboard World, R71 i18n, R77 dynamic labels,
R82 incident mode и серверные role isolation продолжают исполняться
в той же обязательной CI матрице.

## Что это НЕ подтверждает

В этой волне не проводилась независимая WCAG 2.2 AA проверка с VoiceOver,
TalkBack, NVDA, реальными пользователями с инвалидностью, iOS Safari или
Android Chrome при 200% font scaling. Список мест, где сервер возвращает
русские текстовые ошибки (вместо языково-нейтральных кодов), остаётся
для будущей отдельной локализации API с контрактными тестами.
Честная отметка R87: **доступность форм — код и Chromium проверены,
международное качество продукта в целом — не завершено**.
