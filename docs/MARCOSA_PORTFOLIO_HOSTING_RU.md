# MARCOSA: каталог и безопасная схема адресов

Состояние сверено с репозиторием `main` 17 ноября 2026 года. Это реестр для планирования, а не свидетельство запущенных сервисов.

## Рекомендация по размещению

MARCOSA остаётся отдельной социальной сетью и может содержать каталог/добровольные рекламные переходы. Каждый опубликованный продукт сохраняет собственный бренд, кодовую базу, политику данных и независимый origin.

1. **Закрытая проверка:** отдельная staging-среда на origin, принадлежащем владельцу. Не направлять на неё пользовательские домены.
2. **Preview:** при наличии подтверждённого контроля DNS можно выдавать отдельный поддомен на продукт (например, `<slug>.preview.<owned-domain>`), с пометкой «Предпросмотр» и без общих cookie между продуктами.
3. **Публичный релиз:** использовать уже принадлежащий продукту домен. Если его нет, отдельный поддомен под подтверждённым доменом владельца допустим как временный адрес; перед выпуском проверить права, DNS, TLS, сборку, хранение данных и откат.
4. **MARCOSA:** одна карточка обнаружения с описанием статуса и добровольной ссылкой на отдельный origin. Не встраивать разные приложения в один runtime и не перенаправлять домены без подтверждения владения.

Уникальный поддомен помогает изолировать приложение и cookie, но сам по себе не подтверждает бренд, права или production-готовность. Разные поддомены одного registrable domain всё ещё имеют общую границу site для ряда браузерных механизмов; для недоверенных приложений отдельный зарегистрированный домен обеспечивает более сильную изоляцию.

## Кино-реестр

`inventory/film-sites.csv` содержит 43 строки FILM-01…FILM-43. Во всех строках отсутствуют домен, название, жанр, репозиторий и подтверждение прав; статус — `unverified_missing_domain`. Это слоты реестра, а не 43 готовых кино-сайта. В архивах R15 существуют лишь отдельные пути кино-исходников; каждый фильм нужно сопоставить с конкретным исходником, лицензией и сценарием публикации отдельно.

## Выпускной gate

Ни один продукт не получает публичный домен, пока не зафиксированы: владелец домена, точный исходник/commit, сборка, права на контент, модель хранения/авторизации, TLS, тест маршрутов, мониторинг и откат. Настоящий production не меняется этим документом.
