# MARCOSA R129 — проверяемая карта маршрутов preview и исторический разрыв совместимости

**26 октября 2026. Production: NO-GO.** Этап R129 НЕ восстанавливает старые модули из воздуха и не заменяет текущий `marcosa.club`.

## Реально выполнено

- В GitHub Actions добавлен read-only анализ текущего публичного дерева `site/`: общее количество и размер исходных файлов, список HTML-маршрутов и их статических локальных ссылок.
- Отдельно фиксируются кандидаты отсутствующих исходных ресурсов, количество внешних ссылок, небезопасных схем, форм и динамически непроверенных путей. Полные внешние URL, содержимое JS/HTML, значения cookie и токенов в JSON не выводятся.
- Детерминированные тесты отказывают при симлинках, небезопасных именах, неверном SHA и попытке выдать наличие файла за подтверждённую аутентификацию.
- Автоматически сопоставляется список пяти **исторически наблюдавшихся**, но отсутствующих в текущем preview модулей:
  `developer-console.js`, `interaction-bridge.js`, `marcosa-config.js`, `marcosa-supabase.js`, `nexus.js`.
- Артефакт `marcosa-r129-preview-legacy-gap.json` фиксирует **NO_GO** независимо от того, прошёл ли сам анализ. CI PASS означает только успешное построение безопасной карты исходников.

## Что означает исторический R118

[Read-only R118 №40244992341](https://github.com/osmanosmanov6880-bot/marcosa-fusion/actions/runs/40244992341) подтвердил для `5a5111d01bfb55509ea634509c1170997a16a329` 34 файла старого публичного корня, 33 файла только в старой версии и 5 критических интеграций. Это **не является текущим аудитом сервера** и не подтверждает, что старые маршруты или Auth всё ещё ведут себя так же.

Статический HTML-анализ не исполняет JavaScript, не знает динамических `fetch` и SPA-роутинга, не проверяет runtime cookies, реальный API или приватный Storage. Отсутствующая ссылка в исходном `site/` может появляться на этапе сборки и не считается доказанной HTTP 404.

## План безопасного восстановления совместимости

| Зона | Конкретное условие до production |
| --- | --- |
| Пять старых модулей | Получить разрешённый исходный код либо авторизованные схемы API/поведения и написать воспроизводимые контракты каждого модуля. Не использовать пустые заглушки. |
| Маршруты / deep links | Проверить настоящие старый и новый origin через браузер/HTTP, включить формы, коды ответа, мобильную навигацию, CSP. |
| Auth / Session / Cookies | Подтвердить действующий Auth-проект, реальные JWT staging-аккаунтов, MFA/восстановление и сохранение пользовательских сессий. |
| PostgreSQL + private Storage | Создать защищённую резервную копию **реальных** данных и независимо восстановить её в отдельном окружении; проверить RLS, пути медиа, export/delete и RTO/RPO. R128 доказал только **синтетическое** восстановление PostgreSQL 17. |
| Release | Документированное человеческое разрешение, canary и rollback только после всех доказательств. |

Серверное состояние нельзя угадывать по успешной публикации статического preview. Старый root, Nginx, DNS, Auth и пользовательские данные остаются нетронутыми. Глобальные задачи: [#135](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/135) и [#55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55).
