**Контрольное состояние: 25 октября 2026.** Источник: репозиторий `osmanosmanov6880-bot/marcosa-fusion`, базовый R53 план и релизный gate [Issue #55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55). Этот документ содержит **критерии реального завершения**, не произвольные номера версий.

- **R60**: UI-driven Chromium прохождение полного медиацикла на 1440/390/360, 24 кадра и 40/40 Node тестов; PR #74 merged, `8c759203fd845572fc6f0faac234d4a7adca0156`. Работающий пользовательский код в local lab; **не** live Storage.
- **R61**: приватный security-invoker PostgreSQL eligibility view для одобренных PNG с fail-closed отзывом полномочий; PR #75 merged, `5f61529a1defceb3c0c019fce23df60eb299bd81`. Проверен в disposable PostgreSQL 17, **не** применён к Supabase.
- **R62**: добровольная локальная модель D7/D30, явный отзыв и удаление данных, реальный HTTP/Chromium QA — PR #76; статус определяет только GitHub merge и точный CI.
- Никаких доказанных live Supabase Auth, Storage, paid revenue, реального D7/D30, мирового HTTPS STAGING и подписанного go/no-go **нет**. `list_projects: []` — внешний blocker. SSH pin на STAGING не менять, пока не подтверждён независимым источником.

## Очерёдность исполнения

Критический путь: **R63 → R64 → R65 → R66 → R68 → R69 → R70**. R67 (коммерция) проектируется параллельно, но не запускается раньше юридической проверки и независимой технологической приёмки. Продвигать код, SQL-контракты, UI и тесты можно заранее; утверждать боевую готовность — нельзя.

### R63 — настоящая инфраструктура и цепочка доверия

**Инженерные работы:** документировать владельцев сервера/домена/БД и ключей, проверить подлинный ED25519 fingerprint через *независимую* панель провайдера; устранить только подтверждённое расхождение SSH pin; выпустить HTTPS STAGING на изолированном hostname; ограничить доступ ролей, сетей, deploy-пути и секретов; добавить отключаемый canary, неизменяемые build artifacts и rollback с фактической проверкой.

**Автоматизация:** GitHub Actions проверяет подпись артефактов/SHA, строгую SSH идентичность, TLS/HTTP, журналы развёртывания, функцию rollback и правильную сеть. Автоуспех сборки не является разрешением открыть внешний сервер.

**Приёмка:** подтверждение владельца через провайдера, действительный TLS, фактический STAGING URL, лог успешного SSH identity check, два последовательных deploy/rollback и восстановление. **Сейчас BLOCKED**: точный публичный ключ не подтверждён; приватные ключи и пароли в issue не помещать.

### R64 — единственный настоящий Auth/PostgreSQL фундамент

**Инженерные работы:** подключить **существующий** проект Supabase законным владельцем; read-only inventory Auth, Data API exposure, Storage, extensions, backup и схем. Миграции R30/R37/R41/R43/R46/R51/R55/R58/R61 сначала на staging/branch, согласованная модель SQLite→PostgreSQL; RLS всех exposed tables, app_metadata для ролей модератора, revoke/recovery/MFA, rate limits, refresh и session revocation; ограниченный trusted backend.

**Защита:** никаких `service_role`/secret key в браузере, security-invoker для exposed views, явные grants с включённым RLS, `USING`+`WITH CHECK`, отсутствие `user_metadata` авторизации. Не автоматически создавать платную организацию или проект.

**Приёмка:** два независимых настоящих JWT + гость + модератор, матрица чужих чтений/записей, email verification/recovery/MFA, блокировки, приватность черновиков, backup/restore, Security Advisor. **Сейчас BLOCKED**: `projects: []`.

### R65 — production-медиа, безопасность и права на контент

**Инженерные работы:** private upload bucket и обработка PNG/JPEG/WebP в изолированном сервисе с real content sniffing, ограничением декомпрессии, квотами на автора, CSAM/опасные материалы по юридически утверждённой процедуре, ручной эскалацией и журналом модерации. Карантинное хранилище и публичная derivative-выдача раздельно. Подписанные короткие ссылки выдаются только после повторной проверки app_metadata reviewer role + текущей приватности World/блокировок. Обязательные takedown, copyright appeals и deletion of objects/backups согласно политике.

**Приёмка:** полный реальный сценарий World→загрузка→private pending→review→approved→public→reviewer role revoke→public blocked→replace→delete; два аккаунта + модератор + неизвестный гость. Проверить остаточные CDN кеши, stale URLs, отсутствие metadata leakage, multipart race, malware, права и Storage policies. R60/R61 полезны как лабораторные тесты, но **не заменяют этот блок**.

### R66 — мировой продукт и UX без показного футуризма

**Инженерные работы:** продолжить тихую премиальную luxury-визуальную систему с крупной читабельной типографикой и качественными настоящими медиа; полноценная RU/EN локализация всех настоящих экранов и ошибок, адаптивность 320–1920, клавиатурные сценарии, screen readers, focus management, contrast, alt text, WCAG 2.2 AA, SEO/OG серверной страницы World. Сохранить реальные механизмы: профили, Worlds, discovery, комментарии, подписки, уведомления, личные блокировки, апелляции, редакторы и account export/delete.

**Приёмка:** независимые пользовательские тесты desktop и физических Android/iOS, в т.ч. медленные сети, reduced-motion, ошибки загрузки, отказ по квоте, XSS/CSRF/IDOR; Core Web Vitals LCP/INP/CLS на реальном STAGING. **Реализация локального медиацикла ≠ приёмка живой соцсети**.

### R67 — реклама, платёжное право и доказуемая экономика

**Инженерные работы:** верифицировать рекламодателя и права на бренд, получить согласие владельца World, независимая проверка и отзыв; server-side ledger доставки со строгой идемпотентностью, подписанные payment webhooks с replay protection, возвраты, комиссии, налоги, договоры, маркировка рекламы, anti-fraud, idempotent campaign deactivation и доказуемые receipts.

**Приёмка:** настоящая тестовая платёжная операция разрешённого провайдера, повторы webhook без удвоения оплаты, отключение кампании, возврат/ledger reconciliation, реальные verified impressions после внешнего измерительного аудита. До этого `verifiedAdImpressions=null`, `paidRevenue=null`, никакие тестовые заявки нельзя продавать как оплаченные показы.

### R68 — приглашённая бета и настоящий спрос

**Инженерные работы:** дать согласие/удаление данных участнику и записывать реальные denom для приглашённых коорт; минимум 10 независимых интервью с авторами и минимум 10 — с потенциальными рекламодателями; 10 usability-сессий без подсказок; затем добровольная закрытая когорта с реальными World, постами и ответами, оценка D7/D30 только после календарных дней, собранные коммерческие письменные запросы, поддержка и апелляции.

**Приёмка:** датированные, согласованные отчёты фактических (не seeded CI) пользователей; first World, first publish, useful reply, возвращение, каналы привлечения, реальные отказы, минимум 3 письменных B2B pilot requests. R62 на локальной базе не является подтверждением удержания реальных пользователей.

### R69 — готовность эксплуатации, независимый red-team и восстановление

**Инженерные работы:** план реагирования, оповещение on-call, метрики p95/p99 API/media, ограниченный canary с реальными типичными объёмами, backup/PITR/offsite и фактический restore, злоупотребления, object-level ACL audit, dependency scan, SSRF/XSS/IDOR и rate-limit load; внешний аудит безопасности, доступности и приватности для выбранных юрисдикций.

**Приёмка:** журналы load, incident drill, независимый pentest с исправленными critical/high, успешный rollback и restore на отдельном окружении, обоснованное SLO. CI без настоящих пользователей не даёт гарантий мира.

### R70 — внешний go/no-go и мировой релиз

**Инженерные работы:** собрать релизный dossier `commit SHA / live URL / verified SSH fingerprint procedure / TLS / connected Auth & Storage / real two-JWT RLS / media lifecycle / lawful contracts / beta cohorts / load & restore / independent audit / incident policy`. Отдельно назначить владельца release, безопасности, правовой проверки и эксплуатации.

**Стоп-правило:** `node ops/check-release-gate.mjs --profile public` обязан оставаться `BLOCKED` без всех фактических артефактов. Даже `READY_FOR_INDEPENDENT_REVIEW` не публикует автоматически; требуется *человеческое* независимое sign-off. Canary ограничивается, rollback проверяется, затем поэтапное расширение. **Сейчас GO запрещён.**

## Единая матрица release proofs

R63 расширяет fail-closed профили `beta/public` новыми отдельными подтверждениями: проверенный recovery/MFA, private media ACL, quarantine/content review, подписанная медиа-выдача с отзывом, проверенный экспорт/удаление медиа, идемпотентные payment webhooks и процедуру takedown. Полный список находится в `ops/check-release-gate.mjs`. Их отсутствие означает BLOCKED, а не 0/100 или готовность по макетам.

**Выпуск определяется реальным трафиком, юридической ответственностью, реплицируемой безопасностью и пригодностью платформы для пользователей, а не номером R70.**
