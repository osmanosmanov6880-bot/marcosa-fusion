# MARCOSA R46 — PostgreSQL-контракт секретных приглашений

Этот документ относится к **изолированному PostgreSQL 17 в GitHub Actions**. Он не выдаёт наличие текущего Supabase-проекта: подключённый инструмент показывает `projects: []`.

## Что реализовано

- `marcosa_private.pilot_invites`: UUID приглашения, SHA-256 от криптографически случайного кода, создавший оператор, метка, время выдачи/истечения, факт использования, отзыв.
- Чёткие DB-ограничения: код представлен строго 64 символами SHA-256 hex; один хэш не может дублироваться; TTL максимум 168 часов; использованное и отозванное приглашение не могут одновременно иметь такой статус.
- `used_by ON DELETE SET NULL` вместе с `used_at` сохраняет доказательство погашения даже после удаления аккаунта — удаление участника **не открывает** одноразовое приглашение повторно.
- В schema `marcosa_private` браузерным ролям нет `USAGE`, на таблицу нет `SELECT/INSERT/UPDATE/DELETE`, RLS включён как второй рубеж. Ни visitor, ни обычный автор, ни модератор со своим JWT не получают прямого Data API доступа.
- Условия атомарного server-side redemption: `UPDATE ... WHERE used_at IS NULL AND revoked_at IS NULL AND expires_at>now()` с контролем ровно одной изменённой строки в одной транзакции регистрации.
- Реальная PostgreSQL 17 автоматическая проверка отказа anonymous/тестовых JWT Alice и Bob, uniqueness, TTL, однократного погашения, статуса после удаления участника и FK-каскада после удаления оператора.

## Границы

Это не готовый production backend: будущий доверенный сервис должен на настоящем Supabase Auth проверить администраторские права из доверенного источника, лимиты выдачи, rate limiting, email verification, rollback, защищённое распределение секретов, права на аккаунт и ревизию операции. Нельзя помещать `service_role` в браузер или давать публичное исполнение SECURITY DEFINER без аудита.

Для полноценного релиза по-прежнему обязательны безопасный STAGING, юридические документы, реакция на инциденты, реальная закрытая бета и доказанный рекламный спрос. Это контролируется [issue #55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55).

**Проверка:** CI должен пройти исполняемый `tests/postgres/50_rls_pilot_invites.sql` после R30/R37/R41/R43. Статус «завершено» только после успешного CI и merge.
