# MARCOSA R60 — настоящая браузерная приёмка жизненного цикла изображений

**Статус при внесении:** новая обязательная проверка Chromium на локальной социальной платформе; утверждать зелёный результат можно только после CI исходного SHA.

## Что тестируется в реальном браузере

Исполняемый сценарий: `server-lab/test/r60.media_browser_cdp.mjs`. Он поднимает реальный Node 22/SQLite HTTP сервер на `127.0.0.1`, запускает настоящий headless Chromium через DevTools Protocol и проходит **три отдельных набора** 1440×900, 390×844, 360×740.

1. Регистрация реального локального владельца и двух разных модераторов на каждом размере. Роли назначаются исключительно в изолированной тестовой базе, не через пользовательский интерфейс.
2. Владелец входит через браузерную форму. Настоящий `File` PNG устанавливается в input через `DataTransfer`; форма отправляет байты на сервер. Личная обложка видна автору, а публичный HTTP путь отвечает 404.
3. Первый независимый модератор видит PNG и **отклоняет** его через браузер. Автор видит статус и отправляет апелляцию через рабочую форму.
4. Первоначальный проверяющий не имеет доступа к собственной апелляции. Второй модератор принимает её на повторное рассмотрение через интерфейс.
5. Публичный запрос снова возвращает 404 — апелляция сама по себе не публикует изображение. Только последующее независимое одобрение через отдельную кнопку делает публичный PNG доступным по HTTP 200.
6. Новый PNG от владельца сразу снимает публичный статус предыдущего одобрения. Удаление обложки прекращает публичную выдачу, несмотря на прошлую модерацию.
7. В каждом браузерном размере проверяются горизонтальное переполнение, отсутствие сетевых запросов на другие домены и отсутствие необработанных исключений JS.

Сохраняются **21 фактический скриншот** (семь состояний × три размера) в `qa-r60/`, доступный только как краткоживущий CI artifact PR. Это не художественные макеты и не снимки заглушек.

## Как запустить

```sh
node --check server-lab/test/r60.media_browser_cdp.mjs
node server-lab/test/r60.media_browser_cdp.mjs
```

Требуется установленный Chromium/Chrome и Node 22; тест намеренно завершается ошибкой при отсутствии браузера. Секретов, сетевых запросов к Supabase и production-доступа нет.

## Что этот этап не доказывает

Тест проверяет функциональный контракт UI → локальный HTTP → SQLite → UI, а не контентное сканирование, пригодность модерации запрещённых материалов, безопасность настоящего Storage, защищённый HTTPS, email verification, реальные JWT/RLS, законность пользовательских изображений или мировой трафик. Публичный деплой по-прежнему заблокирован Issue #55.
