# MARCOSA R122 — сравнение двух независимых реальных SHA-256 снимков публичного legacy-root

## Задача

R118 нашёл 33 публичных файла старой MARCOSA, отсутствующих в статическом preview, и 5 важных legacy-модулей. R120 отслеживает только индексный SHA, количество публичных файлов и наличие известных имён. R121 создаёт **первый полный публичный SHA-256-инвентарь**, но один снимок не может доказать, что все файлы остались неизменными с прошлого дня.

R122 сравнивает **два самостоятельно собранных реальных R121-манифеста** в разные GitHub Actions-запуски. Если JS/CSS/HTML или изображение изменилось без изменения `index.html`, новый SHA соответствующего файла попадёт в `differences.modified`. Добавление и удаление файлов фиксируются отдельно.

## Защита происхождения

1. В `workflow_dispatch` на `main` оператор указывает **два разных ID** успешных запусков настоящего R121 и два точных 40-символьных SHA. Автоматически выбирать «последний якобы зелёный» запуск запрещено.
2. GitHub Actions с правами `contents: read`, `actions: read` проверяет оба запуска через GitHub API: точный SHA, ветка `main`, событие `workflow_run`, завершение `success`, **успешный именно настоящий job `actual-vps-public-hashes`**. Успешных одних лишь Python/Node PR-тестов недостаточно.
3. Права на сервер и SSH **не используются**. Загружаются только два ранее сохранённых GitHub Actions JSON-артефакта публичных хешей, каждый ограничен 64 КБ. Raw JS/HTML, credentials и аккаунты не загружаются.
4. `ops/r122_compare_public_snapshots.mjs` заново проверяет формат обоих R121, их SHA, запрет production, допустимые публичные имена, размеры, уникальность, сортировку и `sha256OfCanonicalPublicManifest`. Запрос не доверяет произвольным полям из артефактов.
5. Сравнивает публичные файлы по имени, длине и SHA-256. Возможные результаты:
   - **`PASS`**: все допустимые публичные файлы побайтно совпадают между *этими двумя* независимыми аттестованными снимками с точностью SHA-256;
   - **`DRIFT`**: появился, удалён или изменился хотя бы один файл; workflow завершается с ошибкой, но сохраняет обезличенный JSON списка различий;
   - **`BLOCKED`**: неправильный SHA, неудачный серверный job, поддельный исходный артефакт или отсутствующее свидетельство, без «успеха».
6. Артефакт `marcosa-r122-public-drift-verdict` сохраняется 14 дней. Он содержит только общедоступные имена и типы изменений, без файловых байтов и секретов.

## Ограничения

- R122 **нельзя запускать до появления двух настоящих R121 `PASS` с отдельными ID**. Поэтому пока существует только код, тесты и workflow.
- Одинаковые SHA публичных файлов не гарантируют работу авторизации, сохранность PostgreSQL/Storage, устойчивость API, безопасность cookies или совместимость сессий.
- Произвольные изменения публичного `marcosa.club` **не откатываются автоматически**. R122 только сигнализирует и документирует.
- `productionCutoverAuthorized=false`, `productionChanged=false`, `verdict=NO_GO` всегда. Новая статическая версия остаётся на отдельном GitHub Pages origin.

## Реализация

- `ops/r122_compare_public_snapshots.mjs` — независимый строгий компаратор.
- `tests/r122_compare_public_snapshots.test.mjs` — 11 тестов, включая изменение `nexus.js` при неизменном `index.html`, подмену SHA/манифеста, разные источники и безопасность.
- `.github/workflows/marcosa-r122-public-hash-diff.yml` — ручное сравнение **только утверждённых** двух серверных отчётов, никакого SSH или записи.

## Главные зависимости

Для фактического сравнения: дождаться R119 настоящего VPS-прогона, получить R120 и R121 в `main`, выполнить хотя бы два независимых R121 `PASS` и проверить, что предыдущий artifact не истёк (14 дней). Только после этого R122 сможет выдать фактический результат. Production-release по-прежнему зависит от [Issue #135](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/135) и [общего gate #55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55).
