# MARCOSA R79 — аварийное прекращение публичной выдачи изображений (локальная лаборатория)

**Сфера:** локальный Node 22/SQLite, loopback `127.0.0.1` — не Supabase Storage и не глобальный инцидентный пульт.

## Реальное поведение

Если обнаружена утечка приватной фотографии, спорные права на файл или аварийная ситуация, владелец **локальной лаборатории** может временно остановить выдачу **всех публичных PNG-обложек**, не удаляя у авторов файлы и доказательства заявлений о правах.

```sh
MARCOSA_DISABLE_PUBLIC_MEDIA=1 node server-lab/server.mjs
```

Для штатного режима после независимой проверки инцидента, рестарта и повторного одобрения владельца:

```sh
MARCOSA_DISABLE_PUBLIC_MEDIA=0 node server-lab/server.mjs
```

Перед запуском требуется **остановить предыдущий экземпляр** — это параметр конструктора при старте, а не настройка live multi-node. Значение допускается только `0` или `1`; неправильные значения приводят к ошибке, не к неявному включению публичных изображений.

Режим `1` гарантирует:

- `GET /api/worlds/:slug/cover` возвращает HTTP **503** JSON без PNG и с `Cache-Control: no-store`, включая несуществующие URL, чтобы не раскрывать наличие изображения.
- HTML `GET /w/:slug` не публикует OpenGraph `og:image` и по-прежнему содержит `noindex`.
- Каталог `GET /api/worlds`, поиск `/api/discover` и детали `/api/worlds/:slug` имеют `hasCover=0`, чтобы не показывать сломанные миниатюры. Это использует тот же SHA/rights gate R78, а не отключение клиентских CSS.
- `GET /api/me/worlds/:slug/cover` **продолжает** требовать авторизацию настоящего владельца и возвращает ему личное изображение, чтобы автор мог увидеть проблему или предоставить доказательства. Гость получает 401.
- `GET /api/health` возвращает `publicMediaDelivery: "disabled"|"enabled"` без секретов, только в loopback-лаборатории.

Записи `world_covers` и `world_cover_rights` не стираются. После возврата к разрешённому режиму SHA-подтверждённые и независимо одобренные файлы снова видны; прежние заблокированные, отклонённые, лишённые подтверждений PNG и изображения модератора с отозванной ролью не возвращаются.

## Проверка

`node --test server-lab/test/r79.media_incident_kill_switch.test.mjs`: настоящий сервер/SQLite, регистрация и подтверждённая обложка, все пять публичных маршрутов, два реальных открытия базы после перезапуска, конфиденциальный owner-предпросмотр, нулевое изменение бинарного PNG, отсутствие потери прав/согласий и отказ на неверном флаге командной строки. Включён в обязательный CI социальной платформы.

## Важные ограничения

Это **не мгновенный глобальный отзыв CDN-копий, старых подписанных Storage URL и сторонних Telegram/социальных репостов**. В настоящем Supabase production потребуется независимый аварийный флаг на *каждом* экземпляре trusted backend, обязательная валидация JWT при выдаче, отзыв подписанных ссылок, приватные ACL, CDN purge, безопасный on-call процесс с 4-eyes approval, incident audit, срок восстановления и проверка нескольких регионов. Не внедрять в публичный сервис автоматически и не объявлять global incident response готовым по результатам локального теста.
