# MARCOSA R115 — репетиция восстановления STAGING с полным контролем файлов

## Цель

Автоматическая доставка MARCOSA на Contabo уже проверяет файлы и HTTP-ответы перед публикацией. Но прежний ручной откат проверял только существование `index.html` старого релиза. Наличие HTML **не гарантирует**, что JavaScript, CSS и иллюстрации старого релиза остались подлинными.

R115 исправляет именно этот опасный сценарий: **старую версию нельзя сделать активной, пока её собственный manifest, происхождение и SHA-256 каждого файла не проверены повторно.**

## Реализация

- `scripts/rollback-staging.sh`: прежние ограничения пользователя `marcosa-deploy`, папки `$HOME/marcosa-staging` и одобренного маркера сохранены.
- Перед перестановкой указателей Python (встроенный в доставляемый по SSH bash, без внешних зависимостей на VPS) проверяет только кандидата `previous`, не затрагивая `current`: версию исходного коммита, `staging-release.json`, `build-manifest.json`, цель `productionAuthorized:false`, количество файлов, пути и SHA-256 всех публикационных ресурсов.
- Никакие ссылки, обход каталогов, устройства, недопустимые расширения и слишком большие файлы не допускаются. Размеры и число файлов ограничены.
- Проверка `current` **не блокирует** восстановление: активный релиз может быть повреждён, и именно поэтому может понадобиться откат.
- Только после полной проверки готовятся обе временные ссылки и атомарно переключаются `current`/ `previous`. Команды ограничены STAGING, без sudo, Nginx, DNS и `/opt/marcosa/current`.
- В журнале появляются `STAGING_ROLLBACK_TARGET_BYTES_VERIFIED=PASS`, `STAGING_ROLLBACK_TARGET_ASSETS_VERIFIED=<N>` и фактические SHA перехода.
- `tests/test_r115_rollback_integrity.py`: автономная репетиция с настоящим Bash и фиктивными releases. Подтверждает успешное восстановление даже при удалённом индексном файле активного релиза; отклоняет подмену CSS/JS, фальшивое происхождение, небезопасные ссылки и traversal, не меняя текущую ссылку при отказе.
- `.github/workflows/marcosa-r115-rollback-integrity.yml`: обязательные офлайн проверки до объединения с `main`.

## Чего R115 не делает

Этот механизм **не сохраняет клиентские данные** и не заменяет архивы серверных БД; это отдельное восстановление статической STAGING-сборки. Он также не выполняет автоматический откат без зарегистрированного сбоя: автоматизированный текущий SSH workflow может вызвать тот же ограниченный rollback только при сбое после публикации.

Настоящее `https://marcosa.club/` по-прежнему работает из отдельной папки с собственными интеграциями и не переключается. Новый публичный статический предпросмотр продолжает жить на независимом домене GitHub Pages.
