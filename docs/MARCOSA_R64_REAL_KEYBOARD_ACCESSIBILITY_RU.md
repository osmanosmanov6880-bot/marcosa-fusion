# MARCOSA R64 — настоящая клавиатурная доступность без удешевления дизайна

Этот PR исправляет один функциональный барьер: при открытии World через браузер ссылка меняет визуальную панель, но оставляет фокус клавиатуры/скринридера в прежнем месте. Для пользователей клавиатуры это нарушает логическую последовательность навигации.

## Реализовано

1. Реальная ссылка **«Перейти к основному содержанию»**, скрытая до получения фокуса, размещена первой в DOM. Основная зона имеет отдельный `main#main-content[tabindex=-1]`. Enter с клавиатуры переводит туда фактический фокус.
2. При загрузке World (по каталогу или глубокой ссылке) фокус переносится на `h2#world-detail-title[tabindex=-1]`. Зрячий пользователь получает то же плавное перемещение; `prefers-reduced-motion` отключает анимацию.
3. Закрытие через видимую кнопку или клавишу **Escape** внутри World возвращает фокус к той ссылке World, откуда пользователь открыл страницу, а при отсутствии ссылки — к заголовку каталога. Если открыто отдельное диалоговое окно жалобы, Escape не перехватывается.
4. Видимый фокус skip link, усиленные стили при `prefers-contrast: more`, выделение доступной панели и существующий premium-словарь без кислотной графики.

## Жёсткая приёмка (настоящий Chrome CDP)

Сценарий `node server-lab/test/r64.keyboard_accessibility_cdp.mjs` запускает реальный loopback Node/SQLite, создаёт настоящего автора, открывает Chrome 1440/390/360, отправляет **настоящие клавиатурные события** Enter/Escape, проверяет `document.activeElement`, deep link и возврат фокуса, отсутствие горизонтального скролла, внешних запросов и JS-ошибок. Создаёт шесть screenshot-подтверждений в `qa-r64/` для PR artifacts.

## Важные ограничения

R64 — узкий **функциональный** a11y-блок, не заявление о соответствии всего продукта WCAG 2.2 AA. Полный WCAG аудит ещё требует физических Android/iOS, скринридеров NVDA/VoiceOver/TalkBack, цветов/контраста, динамических announcement, формы ошибок и независимого эксперта. Публичная социальная платформа не развёрнута.
