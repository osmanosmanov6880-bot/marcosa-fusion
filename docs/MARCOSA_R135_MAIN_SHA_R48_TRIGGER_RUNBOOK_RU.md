# MARCOSA R135 — R48 должен существовать на каждом текущем main SHA

Дата: 26 октября 2026. Статус: исправление графа GitHub Actions, **production NO-GO**.

## Выявленная несовместимость

Строгий R133 требует пять независимых настоящих доказательств на **одном точном текущем SHA**: R48, Pages, STAGING, R114 и R116. При этом R48 до исправления имел `push.paths` только для `ops/**` и собственного workflow. После слияния исправления R134 менялись только R133 workflow, тесты и документация, поэтому GitHub Actions создавал Pages/STAGING, **но не R48 для нового SHA**. Тогда R133 обоснованно отказывал бы, хотя другие каналы могли быть зелёными.

## Реализовано

1. R48 теперь запускается на **каждый `push` в `main`**, без `push.paths`. Это один read-only `contract-tests` на коммит, а не циклическая `workflow_run` цепочка.
2. `pull_request.paths` остаётся ограниченным исходниками `ops/**`, R48 workflow и собственным R135 тестом. Не запускает SSH в PR.
3. Никаких сетевых развёртываний и прав на запись в R48 не добавлено; `permissions: contents: read`. Код тестирует запрет фиктивного release approval и сохраняет независимое одобрение владельцем.
4. Добавлено 7 регрессионных тестов: глобальный main push, ограниченные PR, точная связка R133/R48, read-only разрешения, ручной профиль, отсутствие `workflow_run` каскада и строгий NO-GO.
5. В R133 по-прежнему требуется успешный реальный R48 job `contract-tests` с event=`push`, точный текущий SHA и другие четыре доказательства. Старые R48 другого SHA не используются.

## Приёмка / порядок

После успешного CI и слияния R135 появится **новый** merge SHA. Дождаться R48, Pages, STAGING и следующих за ними настоящих R114 + R116 **для этого SHA**. Лишь после этого оператор запускает вручную [R133](https://github.com/osmanosmanov6880-bot/marcosa-fusion/actions/workflows/marcosa-r133-automatic-proof.yml). Без успешного R116 реального VPS job R133 обязан отказать.

Затем остаются отдельные read-only/manual R132, R117, два R118, два R121, R122/R127, функциональная совместимость старой платформы, реальное восстановление клиентских Auth/PostgreSQL/Storage, согласование безопасности и явный человеческий GO. Эти условия **не** заменяются R48/R133.

Затронуты только GitHub Actions, тесты и документация. `marcosa.club`, VPS, DNS, Nginx, Accounts, SQL и Storage пользователей не изменяются. **Production NO-GO.**
