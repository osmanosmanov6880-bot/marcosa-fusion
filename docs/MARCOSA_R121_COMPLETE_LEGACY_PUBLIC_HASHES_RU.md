# MARCOSA R121 — SHA-256 всех публичных файлов прежней платформы (только чтение)

## Проверенная исходная точка

[Фактический R118 Contabo audit](https://github.com/osmanosmanov6880-bot/marcosa-fusion/actions/runs/40244992341) зафиксировал: старый сайт `marcosa.club` имеет 34 файла верхнего публичного уровня, а в статическом предпросмотре отсутствуют 33 из них и 5 важных модулей. R120 использует только SHA-256 главного `index.html`, количество файлов и наличие имён пяти модулей. Он **не** проверяет прежние файлы целиком.

R121 закрывает именно этот пробел: собирает новые индивидуальные SHA-256 для **всех допустимых публичных файлов верхнего уровня** существующего webroot, но не изменяет их. Это создаёт первую полноценную публичную побайтовую базу для **будущих** повторных сравнений.

## Механизм

1. На PR запускаются только локальные тесты: реальные временные файлы на Python 3.12 и независимый Node.js 22 валидатор. Production и SSH в PR вообще недоступны.
2. После фактического **успешного R118** на точном текущем `main` с `R117=PASS`, `productionDecision=NO_GO` и `productionChanged=false` workflow R121 скачивает только обезличенный JSON R118 из того же запуска GitHub Actions.
3. Перед подключением к VPS проверяет PIN ED25519 ключа, известный хост, ограниченного `marcosa-deploy`, `StrictHostKeyChecking=yes` и отсутствие устаревания SHA `main`.
4. Через стандартный ввод SSH передаётся строго рассмотренный `tools/r121_public_legacy_fingerprints.py`. На сервере скрипт открывает `/opt/marcosa/current` только для чтения, не следует symlink, не заходит в подкаталоги и перечисляет только верхние `.html`, `.css`, `.js`, `.mjs`, публичные картинки и разрешённые `.json`.
5. Счёт SHA выполняется потоково в ограниченных ресурсах: не более 128 файлов, 32 МБ на файл и 256 МБ суммарно. Файлы `.env`, `secrets.json`, `credentials.json`, `config.json` и скрытые/вложенные пути никогда не читаются. Зафиксированы размер и inode до/после чтения; неожиданная подмена блокирует аудитор.
6. JSON с только публичными именами, размерами и SHA-256 (никакого JS/HTML содержимого) сравнивается с отчётом R118 на том же исходном коммите. Несовпадение SHA старого `index.html`, количества публичных файлов или исчезновение ожидаемого критического модуля возвращает `DRIFT`. Недостоверные схемы и устаревший SHA блокируются.
7. Итог содержит нормализованный список публичных хешей и один контрольный SHA-256 всего канонического манифеста. Сохраняется в GitHub Actions как `marcosa-r121-legacy-public-hashes` на 14 дней. **Никаких SQL-файлов, cookies, сессий, приватной Storage или содержимого файлов** в артефакте нет.

## Очень важное ограничение

У нас **не было прежнего SHA каждого из 34 старых файлов**. Поэтому даже R121 `PASS` означает только «все допущенные публичные файлы текущей версии прочитаны и их хеши сохранены в качестве первой полной базы», **а не** «все 34 файла неизменны по сравнению с октябрьской исторической версией». Для этого потребуется новый R122, который сравнит два независимых R121-манифеста, полученных в разные дни.

В отчёте намеренно всегда: `historicalAllFilesUnchangedVerified=false`, `mainProductionRootCutoverAuthorized=false`, `customerStorageOrAuthInspected=false`, `verdict=NO_GO`.

## Файлы реализации

- `tools/r121_public_legacy_fingerprints.py` — ограниченный потоковый файловый аудитор, без записи на VPS.
- `ops/r121_full_public_inventory.mjs` — сверка SHA, происхождения R118 и sanitization списка файлов.
- `tests/test_r121_public_legacy_fingerprints.py` — 9 Python-тестов.
- `tests/r121_full_public_inventory.test.mjs` — 11 Node-тестов.
- `.github/workflows/marcosa-r121-full-legacy-hash-inventory.yml` — защищённый read-only CI.

**Основной рабочий сайт `https://marcosa.club/` не переключается.** Работы по совместимости аккаунтов, Supabase Auth/Postgres/Storage, резервному копированию и реальному restore остаются отдельными условиями [production gate #55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55).
