# MARCOSA R76 — реальная многопользовательская приёмка записей и изоляции SQLite

**Режим:** только Node.js 22 и локальный временный SQLite, Loopback HTTP. Это не живые участники закрытой беты, не показатели D7/D30 и не проверка production-нагрузки.

## Что стало исполняемым

`server-lab/test/r76.multi_tenant_write_drill.test.mjs` создаёт 12 отдельных аккаунтов с реальным scrypt-хешированием паролей, cookie-сессиями и автоматически созданными Worlds. Нагрузка отправляет 140+ настоящих HTTP-запросов, создаёт публикации, закрытые черновики, подписки и комментарии, затем проверяет:

1. **Изоляция записей:** аккаунт не может записать публикацию в чужой World, изменить чужой пост или поменять чужую обложку/описание World.
2. **Согласованность:** повторная подписка не создаёт дубль; подписки и комментарии сохраняются в настоящей базе, `PRAGMA foreign_key_check` пуст.
3. **Блокировка:** ранее разрешённая подписка удаляется, следующая коммуникация запрещена, персональная лента скрывает заблокированного автора. Анонимный публичный контент не объявляется приватным.
4. **Согласие на измерение:** реальные строки `beta_retention_days` появляются только при явном `POST /api/me/retention-consent`. Другие тестовые аккаунты не принимаются за согласившихся; `retentionD7=null`. Отзыв согласия удаляет приватные дни.
5. **Перезапуск:** после закрытия и повторного запуска отдельной SQLite-инстанции записи, отношения, токены действующих сессий и ограничения сохраняются.
6. **Удаление:** реальный `DELETE /api/account` с повторным паролем и явным подтверждением уничтожает пользовательскую запись, собственные Worlds, публикации и действующую сессию по FK, не удаляя соседний аккаунт.
7. **Параллельные чтения:** поверх реальных записей выполняется отдельный burst из 24 одновременных GET. Результаты должны быть настоящими HTTP 200, ограниченными реальными строками, без fake профилей.
8. **Корректные имена Worlds:** регистрация разрешает подчёркивание в username, но старый генератор порождал `u-username_with_underscore`, который не подходил под собственный валидатор URL. Теперь новые миры получают нормализованный `u-username-with-underscore` с запасным UUID-суффиксом, если подходящий адрес уже занят.

Путь теста `.github/workflows/marcosa-r76-multitenant-lab.yml` содержит отдельный workflow с ограничением прав `contents:read`, Node 22 и полным test-run. Изолированная база удаляется после завершения; никаких данных действительных пользователей на GitHub Actions не загружается.

## Что нельзя утверждать после успеха

12 аккаунтов принадлежат автоматическому тесту. **Это не 12 реальных авторов**, не статистика retention, не proof of product-market fit и не публичная база пользователей. HTTP-нагрузка на одном runner ≠ p95/p99 на настоящем edge с PostgreSQL, приватным Storage и настоящими мобильными пользователями.

**Ранее созданные legacy Worlds со знаком `_`** не переписываются и не теряют существующие адреса. Все серверные маршруты чтения, записи по владельцу и `/w/:slug` теперь распознают исторические подчёркивания, а браузерная навигация не теряет корректную страницу. Новый default slug нормализует `_` в `-`. В PostgreSQL/Supabase эту политику ещё требуется отдельно перенести и проверить; публичной SEO-миграции или автоматических redirect здесь нет.

## Внешний release gate

Supabase Auth/JWT/Storage, доверенный SSH+HTTPS STAGING, права на изображение, настоящие интервью и D7/D30, коммерческие платежи, DR Postgres/Storage, независимый аудит WCAG 2.2 AA и юридическое go/no-go остаются незакрытыми. До их подтверждения Issue #55 остаётся BLOCKED.
