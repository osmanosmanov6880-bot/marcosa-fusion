# MARCOSA R189 — пять независимых блоков, реальный staging по-прежнему NO-GO
Дата: 20 ноября 2026. PR #168, рабочая feature-ветка.

1. Исправлена подтверждённая ошибка R188 CI: `readR187Hold` требует явное имя базы; staging gate теперь использует `holdRead('postgres')`. В R189 добавлен регрессионный тест исходника.
2. `human-approvals.mjs`: отдельные роли SECURITY, OPERATIONS, PRIVACY, отказ при повторяющихся личностях/ролях, синтетическое подтверждение не приравнивается к настоящей проверке людей.
3. `infrastructure.mjs`: exact source-bound contract для GitHub Environment, TLS и фактических AWS permissions; поддельные дополнительные поля и чужой SHA отвергаются; модуль не делает реального провайдерского чтения.
4. `recovery.mjs`: строгая сверка количества и SHA содержимого восстановления, FORCE RLS и закрытого карантина; синтетический readback не объявляется реальным RPO/RTO.
5. `release-gate.mjs`: проверяемая SHA-256 цепочка подтверждений; даже все положительные синтетические заявки заканчиваются `NO_GO_INDEPENDENT_STAGING_ACCEPTANCE_PENDING`. Отдельный GitHub Actions workflow проверяет негативные сценарии.

Контроль: настоящие человеческие подписи, реальные разрешения AWS и GitHub Environment, текущий публичный TLS и независимый restore staging должны проверяться внешними операторами и не могут быть выведены из данных CI. Данный релиз не включает deploy, merge, реальные платежи, пользователей или изменение production.

Статус R188 на момент начала R189: исходный CI завершился FAILURE на ошибке выбора базы данных. Исправление закоммичено, но повторная полная техническая приёмка пока не подтверждена.
