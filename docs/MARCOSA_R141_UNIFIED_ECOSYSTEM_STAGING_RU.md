# MARCOSA R141 — единая витрина проектов без изменения действующего сайта

**Статус реализации:** отдельная ветка, PR-ориентированная интеграция публичного каталога. **Production: NO_GO.** Витрина не является переносом приложений и не разрешает замену legacy.

## Что добавлено

- `site/ecosystem.html`, `site/ecosystem.css`, `site/ecosystem.js`: автономный премиальный каталог с поиском, фильтрами, мобильной вёрсткой и переходами к уже существующим локальным разделам `social.html`, `cinema-pilot.html`, `creator.html`, `film-network.html`.
- `site/ecosystem-manifest.json`: снимок **23 публичных** репозиториев GitHub по данным подключённого аккаунта на **17 ноября 2026 г.** Приватные репозитории не включены и не публикуются из CI.
- Каждая запись содержит ссылку только на исходники. `productionVerified=false` и `marcosaRuntimeIntegrated=false` — независимо от того, насколько презентабельный интерфейс проекта существует в другом месте.
- `tools/build_webroot.py` добавляет только четыре изученных публичных файла в детерминированный allowlist и аварийно отказывает при ложных признаках производственной интеграции.
- `tests/ecosystem_registry.test.mjs` и `.github/workflows/marcosa-r141-ecosystem-contract.yml` проверяют число, уникальность, GitHub-происхождение и запрет на ложный production PASS.
- На существующей главной странице статического preview появляется пятый раздел **ECOSYSTEM**. Навигация не перехватывает настоящий `marcosa.club`.

## Принцип разграничения

1. **Исходник:** GitHub показывает существование публичного репозитория, но не подтверждает работоспособность приложения.
2. **Встроенное превью:** только уже имеющиеся статические локальные маршруты MARCOSA. Не использовать как доказательство настоящих пользователей, регистрации и оплаты.
3. **Самостоятельный сервис:** `osmanx-app-factory`, `osmanx-retail-intelligence` и другие серверные продукты должны получить отдельный security review, изолированные environment/secrets, тестовый URL, health-readback и эксплуатационные runbooks. Статический GitHub Pages не подменяет backend.
4. **Исходников нет в доступной поставке:** репозиторий с README или заглушкой не считается готовым сервисом. Не создавать муляжи и не выдавать ссылку на исходники за опубликованный продукт.
5. **Закрытые репозитории:** не клонировать в публичный `marcosa-fusion`, не открывать и не копировать их секреты. Любая интеграция — по отдельному проверенному доступу и по модели минимальных привилегий.

## Деплой

- **Pull request:** запускать только публичные контракты и существующие сборочные тесты. Никаких SSH в production из PR.
- **Merge в доверенный `main` при зелёном CI:** уже существующие workflow `MARCOSA | Publish public Network OS preview` и `MARCOSA | Build, test and deploy STAGING` могут выпустить новый набор разрешённых публичных файлов на GitHub Pages и отдельную non-root staging-директорию. Верифицировать **точный SHA**, `build`, реальный `deploy_ssh_filesystem`, файл в манифесте и независимый HTTPS readback; общий workflow success со skipped job недостаточен.
- **Основной `marcosa.club`:** ничего не писать в `/opt/marcosa/current`, DNS, Nginx, реальные аккаунты, Supabase Auth/Postgres/Storage. Не выполнять команды root и не активировать `/network-os/` canary без отдельно проверенной модели same-origin isolation.

## Отдельные, всё ещё НЕ закрытые условия для полноценного production

- Достоверный исходный код пяти legacy-интеграций и маршрутные контрактные тесты.
- Реальная резервная копия действующей Auth/PG/Storage системы и **успешное независимое восстановление реальных данных**, а не только синтетических фикстур.
- Проверка сессий, cookies, браузерных хранилищ, legacy-модулей, прав RLS и корректности размещения сервисов в отдельных sandbox/origin.
- Отдельное письменное человеческое GO на конкретный SHA и план отката после независимого readback.

Этот этап **не разрешает production**, не создаёт алиасы или новые DNS и не изменяет текущие серверные сервисы. Технические ограничения смотрите в `docs/MARCOSA_R129_LEGACY_SOURCE_GAP_RU.md` и `docs/MARCOSA_R139_ROOT_CANARY_TRANSACTION_HANDOFF_RU.md`.
