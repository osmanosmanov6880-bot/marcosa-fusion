# MARCOSA R61 — безопасная выдача одобренных медиа: проверяемый PostgreSQL-контракт

**Сделано в репозитории:** новый проверяемый private eligibility view и отрицательные SQL-тесты. **Не сделано:** настоящее Supabase Storage, развертывание production, подписанные ссылки, обработка незаконных материалов.

## Обязательная серверная схема доступа

- Исходный PNG попадает в **private** bucket/quarantine после проверки реальных байтов изолированным обработчиком.
- Независимый модератор выносит решение; хранится кто проверил, что проверено и криптографический digest (R55/R58).
- R61 `marcosa_private.world_cover_delivery_ready` — приватное `security_invoker=true` / `security_barrier=true` представление, которое возвращает ключ только для **одобренного, нормализованного** файла **публичного World**, если у его проверяющего **сейчас** есть роль в доверенном `auth.users.raw_app_meta_data`.
- Самостоятельно изменяемая `raw_user_meta_data` никогда не выдаёт полномочия. После отзыва доверенной роли или перевода World в private объект исчезает из результатов немедленно, без ожидания обновления JWT.
- `anon` и `authenticated` не получают прав USAGE в приватной схеме и SELECT на представление. Ключи не должны возвращаться клиенту через Data API. Эту модель читает только доверенный серверный процесс с ограниченными правами.
- Далее сервер должен подписывать **короткоживущие** URL с проверкой текущих блокировок/прав доступа непосредственно перед выдачей; сам R61 не создаёт ссылки.

## Настоящие автоматизированные проверки

Disposable PostgreSQL 17 в GitHub Actions выполняет все ранее утверждённые R30–R58 SQL и затем R61. Проверяются:

1. Искажение `user_metadata` не создаёт публикацию; проверка нового `app_metadata` даёт ровно одну разрешённую запись.
2. World становится private → доступ исчезает; снова public → может появиться.
3. `quarantined` блокирует выдачу, даже после ранее успешной проверки.
4. Отзыв роли модератора немедленно скрывает объект.
5. `anon` и два типа доступа под `authenticated` не видят private storage_key.
6. Удаление World каскадно удаляет запись, представление не содержит сиротских путей.

## Границы и выпуск

SQL предназначен для ревизии перед созданием настоящей migration через текущую Supabase CLI. Никогда не выполнять данный файл непосредственно над неизвестным live-проектом. Надёжность private Storage bucket/ACL, CDN signed URL invalidation, пользовательская модерация и реальный security audit должны быть независимо проверены на STAGING. Без этого Issue #55 остаётся открытым.
