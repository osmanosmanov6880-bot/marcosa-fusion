# MARCOSA R13 — офлайн-отзывы читателей и аналитика четырёх финалов

**Дата: 24 октября 2026.** Продолжение опубликованного R12. Это функция публичного статического Creator и автономной игры, а не облачная статистика и не централизованный коммерческий аналитический сервис. Публикация на GitHub Pages зависит от CI.

## Пользовательский сценарий

**Автор** пишет историю с двумя выборами и четырьмя финалами, затем скачивает автономный HTML-файл через R12.

**Читатель** открывает этот HTML даже без интернета, проходит два решения и видит один финал. Теперь может добровольно поставить оценку 1–5 и нажать «Скачать отзыв для автора». Небольшой JSON-файл остаётся на устройстве игрока и никуда автоматически не передаётся. Он сам решает, отправлять ли файл автору.

**Автор** открывает новый блок «Тестирование истории», выбирает полученные файлы и видит общую среднюю оценку, количество отчётов и оценки по маршрутам A→A, A→B, B→A, B→B. Можно скачать отдельную сводку JSON или очистить результаты.

## Строгий формат добровольного отзыва

Схема: marcosa-playtest-feedback/v1. Ровно четыре поля:
- schema — фиксированная версия;
- story_fingerprint — hex SHA-256 нормализованных текстов и решений конкретной редакции;
- path — строго две цифры 0/1, например 10 означает B→A;
- rating — целое число от 1 до 5.

**Никаких имени, email, IP, cookie, местоположения, времени, свободного текста и идентификаторов читателя.** Сам текст истории в файл не включается. Внешний мессенджер или почта, которыми человек отправит JSON, могут раскрывать отправителя — MARCOSA не контролирует эти сервисы.

SHA-256 — **идентификатор версии содержания**, не доказательство реального читателя или подпись автора. Любой может изготовить или повторно передать отзыв; количество файлов не является количеством уникальных пользователей, охватом или доказательством коммерческого спроса.

## Работа без интернета и приватность

- Блок оценки появляется только на экране финала. При изменении маршрута выбранная оценка сбрасывается; выгрузка запускается исключительно явным нажатием кнопки.
- Никаких fetch, внешних библиотек, трекеров и серверной статистики. Получателю не нужен WebCrypto во время самой игры.
- Игровой текст остаётся данными в Base64 JSON, выводится только через textContent. Для обновлённого inline JavaScript вычисляется точный SHA-256 CSP hash.
- Импорт принимает **только четыре разрешённых поля**, до 2 КиБ на файл, не более 100 файлов за раз и 300 на вкладку. Если хоть один файл повреждён или относится к другой версии, весь набор отклоняется.
- Если автор меняет текст сюжета в редакторе, предыдущая статистика исчезает из памяти вкладки — для другой редакции нужны соответствующие ей файлы.
- Одинаковые файлы считаются разными поступлениями. Без аккаунтов нельзя достоверно отличить два одинаковых голоса от повторной загрузки одного и того же файла. Поэтому интерфейс называет их отчётами, а не людьми.
- Данные существуют только во временной памяти вкладки, без IndexedDB, cookies и сервера.

## Сводка

Схема marcosa-playtest-summary/v1 содержит story_fingerprint, imported_reports, overall_average и endings[4]. Для каждого маршрута выводятся count, average и distribution[5]. В файле явно указано предупреждение о непроверяемости и неуникальности отчётов. Скачивание вручную; публикации нет.

## Проверки для выпуска

- tests/playtest.test.cjs — whitelist-схема, блокирование посторонних полей, математика средних, привязка к версии, безопасность.
- tools/r12_offline_cdp.cjs — настоящий Chrome file://, 4 пути, 4 файла оценок, проверка содержимого, отсутствия сетевых запросов, desktop/mobile.
- tools/r9_cdp_smoke.cjs — реальный Chrome localhost, импорт 4 отзывов в Creator, корректная сводка, запрет смешивания чужих версий, очистка при редактировании, скриншоты.
- tools/r5_capture_preview.py — десктопное и мобильное изображение новой панели.
- tools/build_webroot.py — строго 16 публичных файлов с SHA-256 manifest; отчёты игроков, ключи и SQL не включаются.

## Границы

R13 — локальный плейтест сюжета из двух решений и четырёх финалов. Это не система коммерческой аналитики, не доказательство спроса, не облачная модерация и не SaaS. Действующие production MARCOSA, Contabo, Stripe и Supabase не меняются. Несовпадение SSH fingerprint на Contabo остаётся отдельной проблемой.
