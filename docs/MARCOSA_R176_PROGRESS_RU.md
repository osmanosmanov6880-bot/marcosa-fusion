# MARCOSA R176 — цепочка подписанных архивов и двойная защита восстановления

Дата: 19 ноября 2026. PR #168. Все изменения только в feature/marcosa-r150-growth-economics.

## Пять инженерных блоков

1. **Целостная история Ed25519**: проверяется каждая версия от генезиса до текущей, два закреплённых ключа, непрерывный parent hash, неубывающие даты, SHA-256 полного объекта, отсутствие повторного объекта, точное совпадение с R174 high-water.
2. **Независимая offsite-проверка**: строго заданные версии S3, полный HEAD+GET через R175 и COMPLIANCE/SSE-KMS/хеш-проверки; отказ при отсутствии версии или подписи.
3. **Двойной одноразовый PostgreSQL 17 допуск**: UNIQUE(sequence) уже в R175; независимые R176 таблицы admission и audit, SERIALIZABLE, строгая проверка R174 high-water, FORCE RLS, NOLOGIN writer без прав UPDATE/DELETE.
4. **Fail-closed координатор**: полная история до nonce, повторная проверка checkpoint после S3, R175 nonce + R176 admission до R173 offsite restore, регистрация инцидента при отказе.
5. **CI и восстановление**: Node отрицательные тесты криптографии/версий/гонок, реальный одноразовый PG17 admission, повторный nonce того же sequence, отдельные соединения, native pg_dump/pg_restore, RLS и независимый второй CI runner с воспроизводимым SHA исходников.

## Ограничения

AWS/S3/KMS в CI синтетические; PostgreSQL 17 и native restore — настоящие одноразовые контейнеры. Нет реальных людей, AWS учётных записей, проверенного Supabase, production RPO/RTO, реальных платежей или deployment. `productionAuthorized=false`. Результаты CI проверяются отдельно; не считать успешными до зелёного run на точном SHA ветки.
