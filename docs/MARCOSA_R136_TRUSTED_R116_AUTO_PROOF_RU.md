# MARCOSA R136 — доверенный автоматический read-only контроль после R116

R136 реагирует исключительно на завершившийся **успешно** R116 в основном репозитории. Он не запускает R116 сам, не выполняет SSH, не меняет production и не вызывает Supabase.

Алгоритм: защитная проверка workflow_run event (точный current-main SHA, имя R116, upstream event, repo и conclusion), ожидание конкретного R114 того же SHA максимум 16 попыток по 15 секунд, строгий повторный R133 просмотр пяти независимых GitHub run/job и двух реальных JSON артефактов. Изменение main, неполные API-страницы, отсутствие R114, skipped jobs, чужой или просроченный артефакт приводят к FAIL. R133 ручной запуск сохраняется.

**Ни один PASS здесь не разрешает production.** В отчёте всегда `productionDecision=NO_GO`. Ручная цепочка R132, R117, два R118, два R121, R122/R127, реальные Auth/PostgreSQL/Storage клиента, совместимость пяти legacy модулей и одобрение владельца остаются вне R136.

Ветка PR: R136 запускает автоматическую проверку лишь **после слияния**, когда сработает реальный STAGING → R116 на новом main; PR тесты могут быть исполнены автономно без доступа к production.

Ранее полученный подключённый Supabase `projects: []` не доказывает владение реальным клиентским проектом. Не создавать его дубль и не переносить данные.
