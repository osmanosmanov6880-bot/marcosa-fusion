# MARCOSA R86 — учёт тестовых возвратов и споров, БЕЗ реальных денег

**Реализовано:** отдельный Node.js 22 модуль, исполняемый SQLite и
проверки идемпотентности. Это следующий слой **offline-лаборатории
R76**, а не платёжный шлюз и не запуск Stripe Checkout.

## Реальный сценарий в тестовой БД

1. До любых финансовых корректировок должен существовать заказ R76 с
   **ранее проверенным HMAC test webhook** и статусом `paid`.
   Неизвестный, не оплаченный или `cs_live_` заказ сразу отвергается.
2. Для возврата предоставляется уникальный `re_test_...` refund ID,
   синтетический `evt_r86_...` event ID, original order,
   ISO currency и целочисленная сумма **в минорных единицах**.
   Тестовый возврат запрещён сверх исходной оплаты.
3. Для спора допустим `dispute_open` с уникальным
   `dp_test_...` ID и суммой не больше остатка после возвратов.
   Пока он открыт, новые возвраты блокируются, а величина
   в отчёте показывается в отдельном тестовом резерве.
4. Спор разрешается **один раз** исходом
   `dispute_won` либо `dispute_lost`.
   После потери спора новые возвраты не могут превысить
   остаток оплаты за вычетом всех предшествующих возвратов
   и потерянного dispute amount.
5. Один и тот же `eventId` с тем же payload SHA-256 возвращает
   `duplicate:true` без повторной проводки. Тот же ID с другим
   payload заблокирован. Новый event с ранее проведённым `refundId`
   тоже отвергается: нельзя выдать один refund за две операции.
6. Все изменения выполняются в одной SQLite
   `BEGIN IMMEDIATE … COMMIT` транзакции. При ошибках
   `ROLLBACK`; FK и история после перезапуска сохраняются.

В журнале **нет реальных клиентов** и внешнего API. Это
исключает случайную обработку настоящих событий в тестовом контракте,
но означает, что событий реального платёжного провайдера здесь
никто не подтверждает.

## Проверка

```bash
node --test ops/payment-contract/stripe-sandbox-contract.test.mjs \
  ops/payment-contract/offline-refund-reconciliation.test.mjs
```

Испытания включают: непроверенный исходный заказ; успешный
подписанный test payment; два частичных возврата, повторную отправку,
несовпадающие тела и refund IDs; запрет превышения суммы;
открытый dispute и отказ в возврате во время проверки;
потерянный и выигранный спор, неверную сумму разрешения,
несовпадающую валюту, отсутствие отрицательного остатка;
несколько валют без искусственной конвертации;
перезапуск настоящей файл-базы SQLite и FK-проверку.

## Честное коммерческое состояние

Отчёт разделяет `simulatedGrossMinor`,
`simulatedRefundedMinor`, `simulatedLostDisputesMinor` и
`simulatedOpenDisputeReserveMinor` по валютам.
Ни одну сумму нельзя называть настоящей выручкой.

`actualGrossRevenue=null`, `actualNetRevenue=null`,
`paymentAccountVerified=false`,
`merchantLegalApproved=false`, `realCustomerCount=null`,
`realSettlementReconciled=false` и
`commercialLaunchAuthorized=false`.

Нет настоящего Stripe API key, клиентов, Checkout API,
подключения Merchant, выставленных счетов, финансового договора,
реальных webhook-подписей refund/dispute, налогов, комиссий,
коммерческого разрешения. Для production необходимы юридически
одобренный платежный аккаунт MARCOSA, официальный SDK и
подтверждение действительных событий `charge.refunded`,
`charge.dispute.created/closed` и их фактических семантик на
текущей версии API; reconciliation с payouts и реальными балансами,
неизменяемый финжурнал, возвраты и финансовые контролёры.

**Не подключать имеющийся аккаунт другого бизнеса и не переносить
данные из этого локального тестового журнала в реальную выручку.**

## Полный мировой релиз

Этот код закрывает только критерий **«проверена модель возвратов и
споров в offline CI»** в R86 из карты R82–R90. Сам этап R86,
включая реальные договоры, Stripe merchant, ставки, налоги и
возможность продавать рекламу, пока **не завершён**.
