# MARCOSA R153 — пять полноценных блоков для авторов и читателей

База: [PR #168](https://github.com/osmanosmanov6880-bot/marcosa-fusion/pull/168). Все функции относятся к **изолированному Node/SQLite пилоту**. Не включаются реальные деньги, production или внешний деплой.

1. **Редактор сезона** — `PATCH /api/series/:slug`: заголовок, описание, дата, ограничение полей и прав автора. HTML-форма `series-meta`, сохранён старый маршрут `next-release`.
2. **Управление эпизодами** — `PATCH/DELETE /api/series/:slug/episodes/:id`, `PUT /api/series/:slug/episodes/order`: переименование, смена порядка, удаление связи с сезоном (не удаляет оригинальную публикацию). Сортировка и удаление атомарны, позиции без дубликатов, смежные отметки и уведомления удаляются через внешние ключи.
3. **Избирательный отзыв согласия** — `DELETE /api/series/:slug/metrics/attendance/:id`: удаляет только отметку текущего пользователя; доступен при заморозке публикаций, с проверкой Origin и пустого JSON. UI показывает кнопки напротив каждого отмеченного эпизода.
4. **Центр напоминаний** — `GET /api/me/series-reminders?limit=20&cursor=...`: курсорная пагинация и `nextCursor`. `DELETE /api/me/series-reminders` скрывает все личные уведомления, в том числе при заморозке, не влияя на другого подписчика. Интерфейс: «Показать ещё», «Скрыть все», индивидуальное скрытие.
5. **Сверенные тестовые ведомости авторов** — `ops/payment-contract/creator-ledger-audit-r153.mjs`: требует реальную внутреннюю двухэтапную R152 сверку, точный SHA-256 источников и соответствие каждого заказа, валюты, автора, частичных возвратов и удержаний. Тестовая выгрузка CSV без пользовательских формул. После новых возвратов, споров или начислений архивные ведомости отвергаются как устаревшие; даже при сохранении общей суммы обнаруживается изменение распределения по заказам.

## Автоматические проверки

```sh
node --test server-lab/test/*.test.mjs
node --test ops/payment-contract/creator-ledger-audit-r153.test.mjs
node tools/browser/author-journey-r152.mjs
```

Ни одна функция **не осуществляет реальных выплат**. Платёжный аккаунт, merchant/legal approval, production Auth/PostgreSQL, независимая проверка SSH/TLS и deploy остаются за пределами R153 и не могут считаться принятыми по лабораторным тестам.
