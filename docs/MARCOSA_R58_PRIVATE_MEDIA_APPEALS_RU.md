# MARCOSA R58 — независимые апелляции отклонённых медиа

R58 — исполняемый PostgreSQL reference contract, **не** миграция в существующий Supabase и не обложки, опубликованные реальными людьми.

## Реализованная модель

- `marcosa_private.world_cover_appeals`: владелец World, текущий SHA-256 отклонённого (quarantined) изображения, обоснование 12–1000 символов, исходный модератор, решение, второй независимый проверяющий и время.
- Private schema, запрет `anon` и `authenticated` на прямое чтение, создание, изменение, удаление; включено RLS. Браузерные JWT не являются полномочием для модераторских решений.
- Доверенный `SECURITY INVOKER` trigger проверяет принадлежность World, SHA текущего медиа и статус quarantine. Исходный модератор захватывается самой базой; человек не может вписать его из JSON.
- Только одно открытое рассмотрение для World; закрытые решения неизменяемы. Исходный проверяющий и автор не могут повторно одобрять собственную апелляцию.
- Исходный материал остаётся **quarantined**, даже когда рассмотрение получает статус `reopened`. Обжалование не публикует изображение автоматически. Для повторного рассмотрения нужна отдельная доверенная серверная транзакция.
- Удаление World/пользователя каскадно удаляет личные данные и апелляции. Прямой пользовательский `service_role` или публикация секретов не допускаются.

## Испытания

`tests/postgres/80_private_media_appeals.sql` исполняется на отдельном disposable PostgreSQL 17 в GitHub Actions после R55. Проверяет три тестовые личности, приватность, вредоносное изменение истории, ошибочного владельца, подмену SHA, повторную открытую заявку, независимость reviewer, невозможность автоматической публикации и каскад.

## Следующий исполняемый блок

R59 должен связать это с настоящими локальными API и UI: создать апелляцию владельца после отклонения R57, показать владельцу собственный статус, отдельный модератор рассматривает заявку без доступа к чужим приватным данным. Если пересмотр успешен, изображение **возвращается в очередь `pending`**, не в `approved`.

**До публичного запуска:** отдельно требуются Supabase Auth + реальные JWT, доверенный API, доступный Supabase-проект, Storage Security Advisor, верифицированный STAGING и независимый юридический/контентный аудит. [Issue #55](https://github.com/osmanosmanov6880-bot/marcosa-fusion/issues/55).
